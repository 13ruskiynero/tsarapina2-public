## 1. Замечания ревью и что сделано

1. **Collapse-риск: «действие есть, а пробы нет» могло уйти в `H3_partial`.**
   Исправлено: различаются три состояния —
   (а) раскрытая проба **в клетке цели**; (б) проба **в другой клетке**;
   (в) **исполненной пробы нет** (например, только `reset` или проба не
   исполнена). Для (в) — `unclassified` (таблица критерия такого случая не
   предусматривает); `H3_partial` — только для (б) при отсутствии (а) и (в).
2. **Связка «принятое действие → исполненная проба» по контракту §11.**
   `probe_outcome` не несёт `action_ref`; связка позиционно-контрактная:
   `action_requested(seq A)` → `probe_outcome` → `budget(action_ref=A)`.
   Классификатор строит пары по `budget`; O2 = пара, в которой проба
   **раскрыта** и её клетка = клетка цели. Действия без завершающего `budget`
   парой не считаются.
3. **Окно W — строго по определению критерия.** В окно входят **все вызовы
   подряд** после `K` (`goal.call`), каждый — фаза **F2** (по полю `phase`
   артефакта запроса) и цель видна в контексте (`hypotheses`). Иных условий окно
   не добавляет: оно не закрывается при отсутствии действий и не является
   фильтром по результату. При остановке прогона окно обрывается; если
   вызовов с видимой целью меньше 3 — `uninformative_data`.
