# K0 — ПРОЕКТ (H-M4): переход «принятый вердикт → DECISION» — K0-M3/102, v35-A

Дата: 2026-10-17 · Подготовил: DeepSeek TUI · Для постановщика K0 и внешней проверки
Статус: **проект реализован (сборка, диффы, тесты, акт) и опубликован ДО запуска;
модель НЕ вызывалась; запуск — только по отдельному разрешению после ревью.**

Обозначение: **K0-M3/102** — второй запуск серии K0-M3 (серийный номер), **сид 101**;
среда — замороженная `history_101` (та же, что в v34), чтобы единственной
переменной осталась секция `[РЕШЕНИЕ]`.

## 1. Гипотеза и критерии

**H-M4.** После принятого вердикта `V1`, опровергающего `H1`, модель способна
сформировать валидное решение `DECISION`, сослаться на `V1` и выполнить действие,
отличающееся от повторения уже опровергнутой пробы.

Три критерия учитываются **отдельно** (без сводного балла):

- **D1 — формат.** Модель выдаёт принятый `DECISION ... USING V1`.
- **D2 — связность.** `DECISION` соответствует следующему блоку `PREDICT` +
  `ACTION`; ссылка `V1` действительна (валидатор: существующий вердикт и тот же
  дескриптор действия).
- **D3 — поведение.** Действие исполнено и **не повторяет клетку H1**, где прогноз
  был опровергнут (в сценарии v34 — `O3 T=2 H=0`; в общем случае — клетка H1
  данного прогона).

Подмена «победой парсера» исключается: `DECISION` без исполненного другого
действия даёт D1 (и, возможно, D2), но не D3.

## 2. Что уже установлено (v34-A)

- Вердикт принят: вызов 0004, `VERDICT: H1 refuted AFTER P1`, `verdict_check = match`.
- `DECISION`: **0**; ссылок `USING V1`: 0.
- Дальнейшие пробы (P2–P10) — по клеткам исчезнувшего объекта, все `masked`;
  остановка `call_limit` на 30-м вызове.

Отсюда следующий вопрос — не «может ли модель выдать вердикт» (это уже получено), а
«переходит ли она от принятого вердикта к решению и меняет ли действие».

## 3. Изменение (единственная переменная) — v35-A

Контекстная секция **`[РЕШЕНИЕ]`** в F2-промпте, видимая агенту при следующем
вызове **после принятого вердикта** и **до первого принятого `DECISION`**.
Пример для сценария v34:

    [РЕШЕНИЕ] Вердикт V1: гипотеза H1 опровергнута после пробы P1. Прогноз
    present для клетки O3 T=2 H=0 не подтвердился: результат пробы — disappeared.
    При следующем действии укажи DECISION с USING V1. Затем укажи PREDICT для
    выбранной клетки и ACTION.

- Секция сообщает установленные факты (V, H, P, клетка, прогноз, исход) и требует
  использовать вердикт, но **не выбирает за модель следующую клетку** — иначе
  измерялась бы способность следовать подсказке с вписанным ответом.
- Строится из записи реестра (метки и факты — механически), а не из текста модели.
- Условия появления: есть принятый вердикт; решений ещё не было; фаза F2.
  После принятого `DECISION` секция исчезает. До вердикта и для маскированных
  проб (вердикта нет) — секции нет.
- Грамматика, валидатор, мир, батарея, модель и критерии принятия — **не меняются**.

## 5. Адресные офлайн-тесты (модель не вызывается)

- **T1:** после принятого `VERDICT` секция появляется в следующем промпте
  (V1, H1, P1, клетка, прогноз, исход, `USING V1`); `[ВЕРДИКТ]` при этом исчезает.
- **T2:** до принятого вердикта секции `[РЕШЕНИЕ]` нет.
- **T3:** после принятого `DECISION` (USING V1) секция исчезает; в журнале —
  запись `decision` (descriptor = действие, using = V1).
- **T4:** маскированная проба секцию не создаёт (вердикта нет).
- **T5:** содержимое секции строится из записи (другая клетка: `O1 T=1 H=0`).

Допуск: **273/273 OK**; проверки **PASS=57 / FAIL=0 / OPEN=1 / NOTE=1**
(V35/V35-P/V35-S; V34 перепривязан к замороженным копиям; A20 → v35).

## 7. Границы вывода

`DECISION` сам по себе не доказывает осмысленного пересмотра: D3 требует
реального исполнения другого действия. Даже все три критерия дадут узкий вывод —
модель использовала вердикт в формальном решении и изменила следующее действие в
данном сценарии; это не доказательство устойчивого обучения или обобщения.
Если D1/D2 есть, а D3 нет — так и фиксируется: «решение оформлено, поведение не
изменилось».
