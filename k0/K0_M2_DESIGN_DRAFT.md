# K0 — ПРОЕКТ ДИЗАЙНА СЛЕДУЮЩЕГО ЭКСПЕРИМЕНТА: обязательный пересмотр гипотезы (рабочее имя K0-M2, сид 101)

Дата: 2026-10-16 · Подготовил: DeepSeek TUI · Для постановщика K0 и внешней проверки
Статус: **ПРОЕКТ. Ничего не разрешает и не запускает.** Модель не вызывается; новые
запуски не выполняются. Основание: итоги аудита использования опыта (факты —
`K0_EXPERIENCE_CHAIN_FACTS.md`; фиксация — `K0_RESULT_FIXATION.md`) и решение:
следующий шаг — спроектировать эксперимент, отличающий реальное использование опыта
от воспроизведения правдоподобного поведения; новых запусков для этого не требуется.

## 1. База для дизайна (факты завершённого прогона v28; заморожены)

- Итог: `acc_before = acc_after = 0.625`, `improvement = 0.0`; 19 вызовов;
  `malformed = 0`; `status = completed`.
- Поведение: 10 из 16 действий — `repeat` (P3–P4 и P9–P16); уникальных
  проверенных клеток — 5; раскрытых исходов агент получил 15 из 16 (P7 —
  маскированная, исход не раскрыт); суммарно раскрытых «disappeared»-фактов — один
  (P5, `O3 T=2 H=0`).
- Контур: `QUESTION`/`HYPOTHESIS`/`VERDICT`/`DECISION` — 0 записей; звенья S1–S5
  не найдены.
- Ключевой вывод аудита: протокол **разрешал** расходовать бюджет без
  обязательного пересмотра модели мира; полный цикл «предсказание → действие →
  результат → пересмотр → проверка пересмотренной гипотезы» не был обязательным.

## 2. Кандидатная гипотеза (формулировка для проверки)

> Если после раскрытого результата агент обязан явно сформулировать, что этот
> результат подтверждает или опровергает в его текущей гипотезе, и обосновать
> выбор следующего действия, то доля повторных действий без новой информационной
> ценности уменьшится, а качество последующих прогнозов может улучшиться.

Два эффекта измеряются РАЗДЕЛЬНО, не смешиваются:
1. **поведение:** реже ли повторяет уже проверенные действия без понятной цели;
2. **модель мира:** улучшаются ли предсказания на отложенном наборе.

Первый эффект сам по себе обучением не является: модель может аккуратно объяснять
каждое действие и по-прежнему ошибаться.

## 3. Новая переменная (единственная): обязательный пересмотр гипотезы в F2

Черновая спецификация (точный текст промпта/норм — в акте после утверждения):

- **Ш1. Перед первой пробой:** обязательны `QUESTION Q1` (со ссылкой `REF:` на
  наблюдение истории) и ≥1 `HYPOTHESIS H<n> OF Q1` с явным предсказанием.
  (Конструкции уже есть в грамматике §7 — новых токенов не требуется.)
- **Ш2. После каждой РАСКРЫТОЙ пробы:** в следующем ответе обязателен пересмотр —
  `VERDICT: H<k> supported|refuted AFTER P<n>` (существующая конструкция;
  механическая `verdict_check` уже реализована).
- **Ш3. Перед следующей пробой:** обоснование выбора — `DECISION: <дескриптор>
  USING V<n>` (существующая конструкция: действие, привязанное к записанному
  вердикту).
- **Маскированные пробы:** остаются в журнале; раскрытым свидетельством НЕ
  являются; ссылки на них в `VERDICT`/`DECISION` запрещены (норма §7 уже требует
  «исход раскрыт агенту»; в M2 — то же правило + отдельная метрика). Никакого
  подмешивания информации, которой у агента не было.
- **Что НЕ меняется:** мир, сид 101, модель, история, батарея E, лимиты
  (30 вызовов / 45 мин / 100k токенов / промпт ≤4000), стоп-критерии,
  механическое ядро проверок. Контекст НЕ получает уведомлений о смене состояния
  объекта (это отдельная возможная переменная будущих серий, не сейчас).

**Реализация — развилка для решения постановщика:**

- **(H) «жёстко»:** отсутствие пересмотра → отказ блока (`action_rejected`,
  новый код `revision_required`), действие не исполняется. Риск залипания
  формата (урок v27) — митигируется явными напоминаниями в промпте.
- **(S) «мягко» (рекомендуется первым шагом):** пересмотр предписан инструкцией
  промпта и **измеряется** (compliance rate по журналу); действие исполняется,
  бюджет не блокируется. При compliance ≈ 0 — эскалация к (H) отдельным решением.
  (S минимален: изменение — только текст промпта F2 + производная метрика.)

## 4. Заранее фиксируемые элементы (до любого запуска)

- **Базовая линия:** результат v28 без изменений (§1).
- **Новая переменная:** одна — обязательный пересмотр гипотезы (§3).
- **Метрики поведения:** число `repeat`; число уникальных клеток; число действий
  с привязкой к вердикту (`DECISION … USING`); compliance Ш1–Ш3; отдельный
  счётчик маскированных проб.
- **Метрики обучения:** `acc_before`/`acc_after` на ОДНОМ И ТОМ ЖЕ наборе E;
  `improvement`; пороги O1 §9 не меняются (0.80; +0.30; статус порогов — как в v28).
- **Защита от самообмана:** критерии и пороги не пересматриваются после просмотра
  результата; правок по ходу нет; маскированные пробы не становятся
  «свидетельством»; отчёт — по фактическим данным; при остановке — фиксация.
- **Предохранители:** без изменений (30/45 мин/100k/≤4000; STOP; `invalid_final`;
  `invalid_f2`). Ожидаемое удлинение ответа F2 (до 4–5 строк: VERDICT + DECISION +
  PREDICT + ACTION [+ NOTE]) — в пределах `num_predict` 256; проверка перед
  запуском на офлайн-сюите (расширить проверки допуска).

## 5. Что должно получиться (заранее объявленная классификация)

- Поведение ↓повторы И обучение ↑acc — переменная сработала по обоим эффектам.
- Только поведение (повторы ↓ / аккуратные вердикты, acc без улучшения) —
  «правдоподобное объяснение без обучения» (ценный отрицательный результат).
- Ничего не изменилось (compliance низкий, поведение как в v28) — обязательный
  пересмотр не меняет поведение модели в этой конфигурации.
Каждый исход фиксируется как результат; интерпретации — после данных.
