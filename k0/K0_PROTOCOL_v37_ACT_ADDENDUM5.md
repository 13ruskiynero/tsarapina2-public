## 1. Замечание ревью (подтверждено)

`derived/rejections.json` (пишет `session._write_rejections()` из
`rejection_audit`) содержит поля `line, phase, kind, label, reason, call,
created` — метка регистрации называется **`label`** (например, `"Q1"`, `"H1"`;
у отказов вердиктов `label = None`). Классификатор же читал `requested` —
на реальных артефактах это давало `None`: **O3 не видел пар Q1/H1**, а O4
ошибочно мог считать отказы вердиктов (`label=None`) «новыми целями». Тесты
использовали `requested` — другая схема, чем фактический источник.

## 2. Исправление

1. Добавлена нормализация метки:

       def _rej_label(x):
           return x.get("label") or x.get("requested")

   (фактическое поле — `label`; `requested` принимается как запасной вариант
   совместимости).
2. **O3** фильтрует пары по `_rej_label(x) in ("Q1","H1")` (kind — question/
   hypothesis, как раньше).
3. **O4** больше не считает записи без метки: `_l = _rej_label(x); if ... and
   _l and _l not in ("Q1","H1")` — отказы вердиктов (`label=None`) не попадают
   ни в O3, ни в O4.
4. Докстрока классификатора дополнена («Ред. 4: фактическая схема — label»).

## 3. Тесты (реальная схема)

- T3: записи `{"call": "0006_F2_a1", "kind": "question", "label": "Q1"}` × 3
  вызова → `pairs = 3`, `singles = 0`.
- T3b: одиночные записи (Q1 в вызове 6, H1 в вызове 7) → `pairs = 0`,
  `singles = 2`, `status = unclassified`.
- **T3c (новый):** отказы вердиктов (`kind=verdict`, `label=None`) → `pairs = 0`,
  `singles = 0`, `O4 = 0`, `status = unclassified`.
- **T3d (новый):** совместимость старой схемы (`requested`) → `pairs = 3`.
- T4d переведён на `label` (`{"call": "0007_F2_a1", "kind": "question",
  "label": "Q2"}`) → `O4 = 1`.
