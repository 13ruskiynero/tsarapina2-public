# K0 — ПРОЕКТ (H-M5): сохранение поведения после решения — K0-M3/103, v36-A

вызывалась.** Опубликован до запуска для независимого ревью.

Обозначение: **K0-M3/103** — третий запуск серии K0-M3 (серийный номер), **сид 101**;
среда — замороженная `history_101` (та же, что в v34/v35).

## 1. Гипотеза H-M5 (устойчивость следующего шага)

Если модель получила контрпример, приняла вердикт и оформила решение, то при
следующем выборе действия она продолжит учитывать этот результат, а не просто
выполнит одну подсказанную команду.

Наблюдаемая цепочка: `VERDICT → DECISION → ACTION → результат следующей пробы →
следующий выбор`.

## 2. Ключевое свойство комплекта: подсказок НЕ добавляется

v36-A — **измерительный эксперимент**: промпты и валидатор **байт-идентичны v35**
(sha256 промптов равен v35 `2721179f…`; проверка допуска V36-P), `calls.py` и
`parser.py` не изменялись. Новых секций, намекающих на клетку или тип действия,
нет вообще — это строже требования «не добавлять подсказок, выбирающих клетку».

Изменения относительно v35 — только: метка версии (v36), имя запуска, пакет
измерительных инструментов (см. §3). Единственная «новая переменная» — глубина
измерения: поведение после **следующей** раскрытой пробы.

## 3. Механическое измерение S1–S3 (зафиксировано до запуска)

- **S1 — первичный переход:** есть принятый `DECISION ... USING V1` и исполненное
  действие (переиспользует D1–D3 v35 как предусловие, не как успех v36).
- **S2 — последовательность:** после результата новой пробы модель снова выдала
  валидный следующий шаг (`PREDICT` + `ACTION`, ссылки валидны).
- **S3 — устойчивость поведения:** следующее исполненное действие не является
  **необоснованным** возвратом к клетке H1.

**Политика повторов (классификатор `scripts/s3_report.py`, тесты T1–T9):**

- возврат (исполненная проба клетки H1) **обоснован**, если:
  (а) между предыдущей пробой этой клетки и возвратом у объекта был `state_change`;
  (б) `PREDICT` возврата отличается от ранее наблюдённого исхода этой клетки;
- иначе — **необоснованный** возврат;
- оба основания могут выполняться одновременно: они считаются **независимо**, общий счётчик — объединение (без задвоения);
- **отклонённые попытки** возврата (`action_rejected` c `probe <клетка>`/`repeat`)
  считаются **отдельно** и НЕ являются возвратами: неисполненное действие нельзя
  засчитывать ни как успех, ни как провал поведения; состояние объекта берётся
  **на момент попытки** (префикс журнала, без будущих записей);
- публикуются раздельно: всего возвратов / обоснованных (по (а)) / (по (б)) /
  необоснованных; попытки: с изменением состояния / без.

**Окно S3:** учитываются только события после принятого решения `USING V<n>`
(если решения нет — после принятого вердикта). Повторные попадания в клетку H1
до окна в S3 не входят и публикуются отдельно (`pre_window_repeats`).
Якорь-решение принимается только при `seq` строго после вердикта; иначе окно
привязано к вердикту (резервный якорь).

Классификатор — только чтение журнала, детерминирован, сеть/модель не использует.

## 4. Как читается результат

- S1+…+S3: «после принятого решения модель продолжила действовать без
  необоснованного возврата к опровергнутой клетке в данном сценарии».
- Если возвратов не было вовсе — S3 отмечается как «вакуумно» (не выдаётся за
  подтверждение).
- Если S2 не наступил (нет валидного следующего шага) — это фиксируется как
  отсутствие последовательности; S3 не оценивается.
- Формулировки «модель научилась», «пересмотр убеждений», «устойчивое мышление»
  не используются: один сценарий этого не доказывает.

## 5. Объём и границы

- Один следующий выбор после результата новой пробы; несколько последовательных
  выборов — отдельный, более поздний этап.
- v26–v35 и их артефакты заморожены; «Царапины 2» не затрагиваются.
- Промпты, грамматика, валидатор, мир, батарея, модель, критерии принятия —
  без изменений.
