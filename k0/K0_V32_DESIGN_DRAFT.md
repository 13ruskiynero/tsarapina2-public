# K0 — ПРОЕКТ СЛЕДУЮЩЕГО ИЗМЕНЕНИЯ: проба по клетке зарегистрированной H1 (v32)

Условие: линия **K0-M3, сид 101, протокол v32** (без переименования серии).
Дата: 2026-10-16 · Подготовил: DeepSeek TUI · Для постановщика K0 и внешней проверки
Статус: **проект реализован и опубликован (акт + диффы) ДО запуска; модель НЕ
вызывалась; запуск — только по отдельному решению после ревью.**

## 1. Проблема (факты v31)

- Инструкция v31 привела к действию, но проба ушла в другую клетку: H1 = `O3 T=2 H=0`,
  пробы = `O2 T=0 H=0` (11 раз); связь «проба ↔ принятая гипотеза» в записях
  отсутствует; `state_change = 0`.
- Отсюда следующий вопрос (по решению): **может ли явная инструкция заставить модель
  выполнить пробу именно в клетке уже зарегистрированной H1** — причём инструкция
  должна опираться на существующую запись гипотезы, а не оставлять модели
  возможность заново сформулировать Q1/H1 с другими параметрами.
- По решению механизм вердиктов одновременно НЕ меняется (иначе не понять, что
  помогло). Переход «раскрытый исход → корректный VERDICT» — отдельным изменением.

## 2. Изменение (единственная переменная) — реализовано в v32

Секция `[СЛЕДУЮЩИЙ ШАГ]` теперь **строится из записи гипотезы** (данные — из
реестра, не из текста модели):

    [СЛЕДУЮЩИЙ ШАГ] Гипотеза H1 зарегистрирована: клетка O3 T=2 H=0, прогноз
    present. Повторная регистрация не нужна. Проверь именно эту клетку: строка
    PREDICT: O3 T=2 H=0 = present, затем строка ACTION: probe O3 T=2 H=0.

(пример отрендеренной секции для реального случая v31; в общем случае — клетка и
прогноз берутся из реестра гипотез, метка — из её номера)

- Условие: `P = 0` и наличие зарегистрированной гипотезы. При нескольких гипотезах
  секция ссылается на H1 (первую по номеру) — зафиксированное ограничение.
- Видимость: контекст несёт `hypotheses` (для F2), а JSON-артефакт вызова
  (`render_context`) включает ключ `hypotheses` — вход секции проверяем без пересказа.
- **Сознательно НЕ включено:** изменения механизма вердиктов; автопреобразование
  регистрации в действие; правки подсказки dup-отказа и строки меток.
- Мир, батарея, критерии, лимиты, параметры модели — без изменений.

## 3. Адресные офлайн-тесты

- **T1 (промпт):** секция с реальными данными H1 (метка, клетка, прогноз) — только
  при `P=0` и наличии гипотез; отсутствует без гипотез и после первой пробы;
  лексикон-аудит; бюджет ≤4000 токенов.
- **T2, T3 (регрессия перехода):** корректное действие после принятой регистрации
  исполняется существующим валидатором; отклонённая повторная регистрация не
  блокирует действие в том же ответе.
- **T4 (новый, привязка):** проба по инструкции исполняется **именно в клетке H1**
  (клетка исхода = `O3 T=2 H=0`; исход раскрыт; в отправленном промпте секция
  содержит эту клетку и метку H1).
- **Предохранитель v30 (R1–R4)** — сохранён отдельно (`test_recovery.py`), не изменялся.
