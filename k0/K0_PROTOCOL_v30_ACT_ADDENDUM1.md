# K0 — ДОПОЛНЕНИЕ №1 К АКТУ v30 (ред. 2 предохранителя `response_loop`)

Дата: 2026-10-16 · Подготовил: DeepSeek TUI · Для постановщика K0 и внешней проверки
Статус: **опубликовано ДО запуска. Запуск по-прежнему НЕ выполняется — ждёт отдельного
решения после просмотра этого дополнения.** v26–v29 заморожены; других изменений нет.

## 1. Замечание (из ревью v30) и подтверждение

Замечание: предохранитель ред. 1 сбрасывал счётчик «застревания», если журнал
менялся, — но повторяющееся одинаковое **отклонённое** действие пишет
`action_rejected`, т.е. журнал растёт без полезного продвижения.

Подтверждено кодом и контрольным прогоном: при прежнем критерии (сравнение
`journal.seq`) тот же сценарий **не** останавливается предохранителем и доходит до
`call_limit`. См. контрольную пару §3(b).

## 2. Исправление (одно; критерий прогресса)

`code/session.py`, блок предохранителя. Прогресс теперь = записи журнала **за
вычетом `action_rejected`** (их счётчик — `malformed`, §7):

    - было (ред.1):  _seq_now = self.journal.seq
    - стало (ред.2): _progress_now = self.journal.seq - self.malformed

Условие срабатывания прежнее: `K = LOOP_FUSE_K = 3` подряд итераций F2, где ответ
байт-идентичен предыдущему И прогресс не изменился → `SessionHalt("response_loop")`.
Одинаковые отказы действия больше НЕ сбрасывают предохранитель; любые иные записи
(пробы, бюджет, регистрации, заметки) — сбрасывают (легитимные повторы проходят,
тест R3). Инвариант: `malformed` инкрементируется ровно в одном месте (число
`action_rejected`, §7) — проверяется валидацией патча.

## 3. Проверки

**(a) Новый тест R4** (`tests/test_recovery.py::test_same_invalid_action_is_fused`):
агент возвращает одинаковое некорректное действие; каждая попытка получает отказ и
оставляет `action_rejected`. Факт (контрольный прогон): **стоп `response_loop` на
6-м вызове; в журнале 4 записи `action_rejected` (журнал рос); до `call_limit`
(30) дело не дошло.**

**(b) Контроль (ред.1, демонстрация дефекта):** тот же сценарий с прежним критерием
(`seq`): **стоп `call_limit`: 30 вызовов, 28 записей `action_rejected`** — полный
расход бюджета вызовов без продвижения. Контрольный модуль собран копией
`session.py` с обратной заменой блока фьюза и удалён после прогона.

**(c) Регрессия:** R1 (восстановление после отказов), R2 (залипание без записей),
R3 (легитимные повторы при растущем контексте) — без изменений, зелёные.
Офлайн-сюита: **247/247 OK** (было 246 + R4; строгий `-W error::ResourceWarning`).

**Допуск:** **PASS=41 / FAIL=0 / OPEN=1 / NOTE=1**. V30-S расширена (ред.2): проверяет
критерий по `last_progress` (отсутствие `last_journal_seq`), наличие R4.
