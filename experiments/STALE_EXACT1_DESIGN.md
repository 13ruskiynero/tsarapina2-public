# TSARAPINA STALE-EXACT-1: ДИЗАЙН (06.09.2026)

**Статус: ДИЗАЙН ОТКРЫТ (профессор). v0.3 НЕ трогаем. Новые
механики — только experimental branch. Критерии зафиксированы
ДО просмотра результатов. Код за воротами до фиксации дизайна.**

## 1. Вопрос (дословно, профессор)

> Что происходит, когда exact-знание существует, но перестаёт
> соответствовать текущему миру?

Это правая граница контура (SEB-1 закрыл левую):
```
                 KNOWLEDGE
                     │
                 exact match
                     ▼
                    S2 / exploitation
                     │
               verified?
              /            \
         YES                NO
          │              (STALE ?)
          ▼                UNKNOWN
       success                │
                              ▼
                        STALE-EXACT-1
```
- SEB-1 (левая): симптом есть, exact НЕТ → broad hypothesis →
  exploration → приобретение. ЗАКРЫТ.
- STALE-EXACT-1 (правая): симптом есть, exact ЕСТЬ → S2 уверенно
  предлагает старое решение → мир его отвергает. Что происходит?

## 2. Гипотеза (проверяется, НЕ истина заранее)

**H-S1: одного отрицательного последствия недостаточно для
автоматического переключения с exact-эксплуатации на exploration
без риска разрушить работающую S2 (шум-устойчивость).**

## 3. Полигон (устаревание как скрытое условие)

tsasvc; класс A: старый мир: lock.a → fix-a лечит (снимает a +
start); новый мир: lock.a + lock.extra → fix-a НЕ лечит (extra
остаётся, демон падает), лечит только fix-a2 (снимает a + extra +
start).

**Политика полигона (изменение, задокументированное):** extra —
СКРЫТОЕ условие мира: сенсор симптома (polygon_sensor) исключает
extra из наблюдаемого симптома. Наблюдаемый симптом болезни
остаётся «a» в обоих мирах: устаревание невидимо по признакам;
видно только по последствиям действий. (Известные болезни
a/b/c/ab наблюдаемы как раньше; fix-a2 остаётся в allowlist.)

## 4. Сценарии

### M0. Контроль (без устаревания)
learn A (старый мир) → эпизод A: exact → S2 → fix-a → success.
**Критерий: 1 действие.** Повтор A — то же. Контроль ложного
срабатывания «знание устарело».

### M1. Однократное устаревание (сырой результат)
learn A (старый мир) → мир переключается в новый → эпизод A.
Ожидаемая базовая траектория v0.3 (F0): exact → fix-a → failure.
**НИЧЕГО не чинить: записать сырой результат.** Контрольная
точка: exact-match не различает «проверенное и актуальное» от
«проверенное, но устаревшее».

### M2. Тот же A второй раз (после failure)
Возможные исходы (регистрируются как есть):
- M2-A: fix-a снова → failure (устойчивая stale-петля);
- M2-B: S3/conflict (конфликтная защита сработала);
- M2-C: exploration → fix-a2 → success (самопереход
  эксплуатация → исследование НА ОСНОВАНИИ собственного
  последствия). C не программируется как ответ: переход должен
  возникнуть из механики F3, а не из `if failure: explore`.

### M3. Контроль с шумом (обязателен)
Класс A, fix-a правильный; один запуск получает ВНЕШНИЙ failure
(синтетический шум-эпизод: действие fix-a, мир ответил failure,
мир НЕ менялся). Затем повтор A (мир старый, fix-a работает).
**Критерий: система НЕ должна искать новое решение после одного
шумового failure** (иначе механизм слишком чувствителен). Граница:
реальное устаревание ≠ единичный внешний сбой. Причинного слоя
нет (TRUST-1) — цена различения измеряется здесь.

## 5. Факторизация (экспериментальные механики, НЕ интеграция)

Ветка strategy_v5 (копия v0.3 + механика; основная не меняется).
Каждая механика прогоняется на ВСЕХ критериях «Сохраняем» и на
M1/M2/M3.

- **F0**: v0.3 как есть (контроль; контурный declare выключен).
- **F1**: после failure-эпизода на exact-классе контур объявляет
  конфликт: declare_conflict(последний success-exact (симптом,
  команда), новое failure-знание) — событие противоречия
  зафиксировано в истории (паттерн auto-conflict зоны 3/T1).
  Выбор — v0.3 (conflicted → S3).
- **F2**: F1 + conflicted exact-знания исключаются из S2-выбора
  (recency-пул = неконфликтованные exact; если exact-пул пуст
  после исключения → S3).
- **F3**: F2 + когда конфликт остановил эксплуатацию exact-класса
  (нет пригодного exact) → exploration=True (систематический
  перебор контура; право искать). Переход обусловлен СТРУКТУРОЙ
  (конфликт в истории), не счётчиком failure.

Запреты: без `if failure: explore()` как «решённой задачи»; без
trust-чисел; без N-failures-эвристики; без causal model; без
изменений Knowledge/Update/Evaluation/Executor/R1.

## 6. Критерии (заранее)

**Сохраняем (каждая механика F0–F3):**
1. M0: известный A = 1 действие;
2. return-A после обычного обучения = 1 действие;
3. AB = 1 действие;
4. SEB-1 C-сценарий не деградирует (C1: гипотеза → exploration →
   fix-c; C2–C7: S2 1 действие; C-серия при F1–F3 не затронута
   конфликтами: у C нет failure exact-пар);
5. S3 для УЖЕ объявленного конфликта не исчезает;
6. swap сохраняется;
7. deterministic trajectory сохраняется.

**Проверяем (M2/M3):**
1. После stale-failure система перестаёт слепо повторять
   устаревший exact-кандидат;
2. exploration действительно может открыть новое решение (fix-a2);
3. шумовой failure не уничтожает рабочее знание (M3);
4. старое знание и его failure остаются в истории (версии);
5. новое решение появляется только после собственного
   проверенного последствия (аудит: знание (a, fix-a2) создано
   после success fix-a2, не раньше).

## 7. Ожидаемые исходы (фиксируются заранее)

- **Boundary 1**: F0: exact → failure → exact → failure (петля):
  архитектура не превращает отрицательное последствие в смену
  режима. H-S1-подтверждение (для «автоматического» варианта).
- **Boundary 2**: F1/F2: exact → failure → conflict → S3: конфликт
  останавливает эксплуатацию, но не порождает исследование —
  TRUST-1 получает продолжение: «конфликт может остановить, но
  сам не порождает исследование».
- **PASS-вариант**: F3: exact → failure → conflict/invalidated →
  exploration → fix-a2 → success → новое знание → S2 (последующие
  A: fix-a2, 1 действие). Цена измеряется на M3: если F3 уводит в
  exploration после шумового failure — чувствительность
  зафиксирована (ложное срабатывание) — тогда результат
  «PASS на устаревании ценой шум-инвариантности» = точная граница
  H-S1: одного последствия недостаточно для БЕЗОПАСНОГО
  переключения; «какое событие делает знание недостаточным» —
  следующий исследовательский вопрос (повторное последствие?
  контекстная переменная? причинный слой?) — НЕ решается здесь
  эвристикой.

## 8. Процедура прогона (после заморозки)

На механику (F0..F3), на чистых сторах:
(a) Сохраняем: learn a → эпизод a (1 действие); return-A (learn
a, learn b → эпизод a: 1); AB (learn ab → эпизод: 1); SEB-C
(learn a/b/ab → C1: exploration → fix-c; C2: S2); S3-объявленный
конфликт → S3; swap (эпизод после знания: S2);
(b) STALE: learn a (старый мир) → переключение мира (extra) →
эпизод 1 (M1; F1+: declare) → эпизод 2 (M2: фиксируется
A/B/C-исход) → при успехе fix-a2: эпизод 3: S2 fix-a2 1 действие;
(c) M3: отдельный стор: learn a → synthetic шум-failure → эпизод a
(старый мир): фиксируется поведение (fix-a success / S3 /
exploration);
(d) аудиты: версии целы; знание (a→fix-a2) создано после
проверенного success; детерминизм (повтор suggest).

Сначала сырые траектории, затем вердикт по исходам.
