## 3. Результаты (halt-семантика; раздельно R и S)

Критерии: stop_on_S = (повторений fix-a после триггера == 0 и
granted→excluded); recovery_on_N = (success после триггерной точки
достижим не позже baseline). Формат: конфигурация [S-история |
N-история].

```
C1  [SD | N1D]:  stop = PASS (0; True)    recovery = FAIL (S3/S3; None)
C2  [SD | NpD]:  stop = PASS (0; True)    recovery = FAIL (None)
C3  [SD4| NpD]:  stop = PASS (0; True)    recovery = FAIL (None)
C5a [S6bV3 | E6N-V3]: stop = PASS        recovery = FAIL (None)
C5b [E6S   | E6N]:    stop = PASS        recovery = FAIL (None)
C6  [—     | C6N]:    stop = n/a          recovery = FAIL (None)
```

- R и S дают ОДИНАКОВЫЕ исходы на всех конфигурациях (в

  в горизонте не влияет).
- Дополнительно: B-линии восстанавливаются во всех N-историях
  (шаг 2/4) — провал recovery принадлежит вмешательству, не

- **Итог: sufficient(right, C) = False для всех C и обоих прав.**

  (S3) в N-средах, уничтожая достижимое восстановление.

## 4. EF-5: семантика exclusion (открыт; решение за профессором)

Симуляция (наследие EP-1/AA-1) реализует исключение как **halt**:
если suggest выбрал исключённый K — эпизод отменяется (S3).
Альтернатива — **pool**: K невидим для suggest → выбор следующего
кандидата. Различие проявляется только в средах с ≥2 success-
кандидатами (E6-семейство, C5):

- halt (измерено): C5-N: recovery=False (S3); C5-S: stop=True.
- pool (ПРЕДСКАЗАНИЕ, не измерено): C5-N: K2 скрыт → выбран K1 →
  fix-a → успех (recovery=True); C5-S: K2 скрыт → K1 → fix-a в w2 →
  failure → повторение (stop=False); C1–C3: однокандидатные среды →
  pool ≡ halt; C6-N: pool: шаг 4 выбирает K1 → успех (recovery=True).
- Устойчивость вердикта: при pool ни одна конфигурация тоже не
  sufficient (провал переезжает с (б) на (а) для C5; C1–C3 без
  изменений). Локализация провала C5 зависит от семантики:
  «постоянное исключение блокирует восстановление» (halt) vs
  «исключение одного кандидата не останавливает контур — второй
  verified-success кандидат продолжает мёртвое применение» (pool).
- RAW не переписывается. При выборе pool — дополнительная волна
  C5+C6 (20 прогонов, отдельные записи); при утверждении halt —
  отчёт финален.

## 5. Вердикт (узкая формулировка, DESIGN §5)

При permanent R/S ни одна из исследованных evidence-конфигураций
(C1 single, C2 repeated, C3 persistent, C4 (a)-divergence — вырожден,
C5 conflict (a)/(b), C6 recovery) не удовлетворила совместному
критерию остановки и восстановления. Это результат EP-2A и основание
открыть **EP-2B** для исследования временной semantics retract/
suppress (permanent vs temporary «до-подтверждения»).

Замечания: тип записи (a)/(b) внутри C5 исходов не различил (оба
класса: stop PASS / recovery FAIL); различие конфигураций проявилось
только в МОМЕНТЕ триггера, не в исходе. Boundarie-вывод: evidence
структура при permanent-семантике исход не спасает — свойство
постоянства права, не структуры evidence (с оговоркой EF-5).
