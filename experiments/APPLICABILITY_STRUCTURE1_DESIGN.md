# TSARAPINA APPLICABILITY-STRUCTURE-1 (AS-2): DESIGN (06.09.2026)

**Статус: FROZEN (профессор: «AS-2: DESIGN → FREEZE → RUN»).**
Прогон разрешён. v0.5 не меняется; measurement-only; сначала
структурные миры (этот протокол), затем ОТДЕЛЬНЫМ экспериментом
learn → applicable_when (второй поток; дизайн после AS-2).

## 1. Вопрос (не «работает ли E∧V»)

> Что происходит с applicability-структурой, когда её составляющие
> сигналы перестают быть согласованными?

Главное различие: **значения сигналов** против **отношения между
сигналами**. Не решать заранее, какой сигнал «прав» в wX/wY:
пара значений не говорит, кто из них каузален.

## 2. Миры (физика применимости fix-a; сигналы E=extra,
V=environment_version; GT = реально ли fix-a лечит мир):

```
w1:   E=absent,  V=1   fix-a ПРИМЕНИМ (лечит; learn-мир)
w2:   E=present, V=2   fix-a НЕ применим (extra; V согласован)
wX:   E=present, V=1   fix-a НЕ применим (extra есть; V слеп)
wY:   E=absent,  V=2   fix-a ПРИМЕНИМ (extra нет; V лжец)
noise: E=absent, V=1   шумовой сбой (fix-a формально верен;
                       внешний фактор n; outcome=failure)
```

## 3. Три уровня (проекции на одних raw-трассах)

- **C1: одиночные условия.** E-одиночное; V-одиночное (эталоны из
  learn: E=absent, V=1). Контроль, чтобы композиция не добавила
  артефакт.
- **C2: конъюнкция E∧V** (условие: E=absent И V=1). Согласованный
  мир, wX, wY, noise. НЕ интерпретировать false как «мир
  изменился»: false — всего лишь результат условия.
- **C3: расхождение как наблюдаемое состояние.** Вектор
  расхождения от эталона: dE = (E_now ≠ E_learn), dV = (V_now ≠
  V_learn); регистрируется ОТНОШЕНИЕ между сигналами (w1/noise:
  (0,0); w2: (1,1) — согласованное изменение; wX: (1,0), wY:
  (0,1) — РАСХОЖДЕНИЕ), а не победитель. Главный тест на B:
  стабильно ли отношение и имеет ли оно отдельное поведение
  относительно GT.

## 4. Метрики (по уровням, к GT-применимости)

верный стоп (не применим → стоп) / ложный стоп (применим → стоп)
/ слепота (не применим → применяем) / верное применение.

## 5. Ожидания (предсказания дизайнера, НЕ результаты)

- C1-E: верный стоп w2/wX; верное применение w1/wY; слепота на
  noise (E не видит n);
- C1-V: верный стоп w2; слепота wX (V=1); ЛОЖНЫЙ стоп wY (V=2);
  слепота noise;
- C2-E∧V: как E, но wY — ЛОЖНЫЙ стоп (V испортил конъюнкцию);
  noise — слепота (применяем при шуме);
- C3: расхождение (1,0)/(0,1) стабильно в wX/wY; НЕ определяет
  GT (wX: не применим; wY: применим — одинаковое отношение,
  разные исходы): «отношение существует, решения не несёт» —
  если подтвердится: B-граница (структура содержит отношение, но
  каузальность сигнала не выводится из пары — нужен внешний
  источник/история); если схлопнется в «просто false» — список
  условий.

## 6. Запреты

без механик в Strategy; не выбирать «победителя» E/V; false ≠
«мир изменился»; D/N/P/S остаются кандидатами ИЗМЕРЕНИЯ (второй
поток), не скрытыми правилами обучения; без порогов.

## 7. Процедура

Регистратор: env → сигналы ДО действия → фиксированное fix-a
через Executor → outcome; опыт/знания не создаются. Миры w1×2 +
w2×3 + wX×3 + wY×3 + noise×3 = 14 эпизодов на реплику; реплики
r1/r2. learn-эталон: w1 (E=absent, V=1) на реплику.
Артефакты: as2_driver.py, AS2_run.log, AS2_records.json,
as2_analyze.py, AS2_ANALYSIS.txt, APPLICABILITY_STRUCTURE1_REPORT.md.

## 8. Второй поток (ОТДЕЛЬНО, после AS-2; не запускается сейчас)

learn → applicable_when: измерение «какие из доступных фактов
должны попасть в applicable-condition при обучении»; исходный
фильтр — AS-1-свойства (pre-action, outside symptom, stable,
changes with applicability, FP=0/FN=0, expressible). D/N/P/S —
кандидаты измерения, не правила.
