## 1. Журнал → механика: сырые траектории (сводно)

Четыре события, прослеженные по каждой механике:
EXACT_SELECTED / ACTION_FAILED / CONFLICT_DECLARED /
EXPLORATION_GRANTED — какое ВПЕРВЫЕ меняет режим.

```
мех.  preserve  stale ep1             stale ep2                  noise (M3)
F0    6/6 ✓     EXACT fix-a→FAILED    EXACT fix-a→FAILED          EXACT fix-a→OK
             (режим не меняется)    (петля; M2-A)               (шум-устойчив)
F1    6/6 ✓     EXACT fix-a→FAILED    [CONFLICT]→S3_STOP          [CONFLICT]→S3_STOP
             →CONFLICT_DECLARED      (M2-B)                      (ложн. срабатыв.)
F2    6/6 ✓     →CONFLICT_DECLARED    →S3_STOP (M2-B)             →S3_STOP (ложн.)
F3    6/6 ✓     →CONFLICT_DECLARED    →S3_STOP→EXPLORATION_       →S3_STOP→
                                       GRANTED→перебор: start,    EXPLORATION→
                                       restart, fix-a, fix-b,     перебор→fix-a OK
                                       fix-ab fail→fix-a2 OK      (ложн. срабатыв.)
F3 ep3: S2 fix-a2 → success (1 действие)
```

Preserve 6/6 на всех механиках: A=1 действие; return-A fix-a;
AB fix-ab; SEB-C (C1 гипотеза→exploration→fix-c через 7 шагов
перебора, включая fix-a2; C2 S2 fix-c); S3 объявленного конфликта
(sid S3 сохранён); детерминизм.

**Какое событие впервые меняет режим:** ACTION_FAILED — НИГДЕ
(F0: два failure подряд, режим не меняется — петля). Режим меняет
CONFLICT_DECLARED (F1–F3: эксплуатация → S3-остановка); в F3 за
ним следует EXPLORATION_GRANTED (S3-остановка → поиск). Т.е.
переключает не само последствие, а зафиксированное в истории
противоречие; но фиксация (declare по одному не-success)
генерируется ОДИНАКОВО для устаревания и для шума.

## 2. Критерии «Проверяем»

1. Перестаёт слепо повторять устаревший exact-кандидат: F1–F3
   (F0 — нет: петля);
2. exploration открывает новое решение: F3 (fix-a2; 6-й шаг
   перебора);
3. шумовой failure не разрушает рабочее знание: F0 — да
   (fix-a → success после шума); F1–F3 — знание НЕ удаляется
   (версии целы), но эксплуатация останавливается/уходит в поиск
   — ложное срабатывание (M3-критерий «не искать» нарушен F1–F3);
4. старое знание и failure остаются в истории: аудит stale_F3:
   K(success fix-a) v1 active → v2 conflicted; K(partial fix-a)
   conflicted; обе пары целы; конфликтная пара одна;
5. новое решение только после проверенного последствия: аудит:
   K(fix-a2) создан в опыте ep2 (последнее действие перебора =
   fix-a2, success); знания fix-a2 до успеха нет.

## 3. Интерпретация (только после журнала)

**Главный критерий дизайна:** может ли система отличить
свидетельство устаревания exact-знания от недостаточного для
такого вывода единичного failure — без trust, без N-failures, без
причинной модели?

**НЕ МОЖЕТ — ни одна механика.**
- F0 не отличает: не реагирует ни на что (устаревание = шум =
  обычный failure: эксплуатация продолжается; M2-A-петля);
- F1–F3 не отличают: declare по одному не-success срабатывает и на
  устаревании, и на шуме (ложное срабатывание: после шумового
  failure эксплуатация останавливается (F1/F2) или уходит в поиск
  (F3));
- F3 «достигает fix-a2» на устаревании, НО это не PASS: M3
  показывает, что единичный внешний failure на исправном классе
  отправляет систему в exploration.

**Вердикт: BOUNDARY (граница ложного срабатывания).**

**H-S1 подтверждена (сильная форма):** одного отрицательного
последствия недостаточно для БЕЗОПАСНОГО автоматического
переключения exact → exploration: цена авто-переключения по
одному не-success = потеря шум-инвариантности (работающая S2
останавливается на единичном внешнем сбое). «Автоматическое»
переключение без различения источника — это не обнаружение
устаревания, а генерализация шума в смену режима.

**Карта зоны (что установлено):**
```
F0: stale-слепота: не-success не меняет режим; петля;
F1/F2: конфликт-фиксация останавливает эксплуатацию (и при
       устаревании, и при шуме); поиск не возникает сам;
F3: конфликт-остановка + право искать: recovery fix-a2 на
    устаревании; на шуме — ложный поиск (возврат к fix-a через
    перебор — но режим уже переключён);
ни одна механика не отличает устаревание от шума.
```

**Какое событие делает знание недостаточным (ответ-граница):**
событие-кандидат «не-success exact-последствие» НЕ является
достаточным свидетельством: оно одинаково для устаревания и для
внешнего сбоя. Знание становится «недостаточным» только в смысле
«зафиксировано противоречие» — но фиксация по одному последствию
слишком чувствительна. Различающий сигнал (повторное последствие
во времени? контекстная переменная? причинный слой?) отсутствует
в контуре без trust/N-failures/causal model — и его природа
становится следующим исследовательским вопросом (НЕ решается
эвристикой: любая эвристика «после K не-success» была бы тем же
неразличением с порогом).

**Следствие для TRUST-1 (как и предполагалось):** конфликт может
остановить эксплуатацию (F1/F2), но сам по себе не порождает
исследование (F3 добавляет право искать — ценой шума). Вопрос
доверия остаётся событийным (success/failure/conflict/recovery);
числовой trust не нужен — но событие «достаточное свидетельство
устаревания» не найдено.
