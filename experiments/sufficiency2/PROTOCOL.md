# TSARAPINA SUFFICIENCY-2: PROTOCOL (FROZEN 06.09.2026)

Дизайн: SUFFICIENCY2_DESIGN.md (FROZEN). Прогон — измерительный
(регистратор, НЕ стратегия): v0.5 не изменяется; контур исполняет
S2 → fix-a; переходы НЕ исполняются (регистрируются офлайн).
Порядок интерпретации: сырые серии → распределения → hold-out →
A/B/C. Никаких изменений после этой заморозки; дефекты не чинятся
по ходу (фиксируются, прогон перезапускается только целиком).

## 1. Ячейки матрицы

Фоны (шум-генератор p на исправном мире a: с вероятностью p
эпизод ставит скрытый n — fix-a не лечит; иначе мир a — fix-a
лечит; n скрыт от Observer):
- low: p = 0.05;  high: p = 0.35;
- variable: эпохи по 15 эпизодов, чередование p=0.05 / p=0.35
  (начинаем с 0.05).

Классы на каждом фоне (6 серий; колонка stale+noise дизайна ≡
stale при фоне — зафиксировано):
- noise: мир a весь прогон (шум p);
- stale: эпизоды 1..30 как noise (мир a, шум p); С ЭПИЗОДА 31:
  мир w2 (a + extra; extra скрыт; fix-a больше не лечит; шум-фактор
  после t0 неразличим и не нужен — все эпизоды non-success).

Каждая серия: learn fix-a (мир a, чистый) на свежем сторе, затем
60 эпизодов. Повтор серии: второй прогон с новым seed шума
(детерминизм шум-генератора: seed = параметр серии; два повтора:
seed_r1, seed_r2). Итого 12 прогонов серий.

## 2. Регистрация (офлайн, правила ДО измерения)

История серии: outcomes[1..60] (success/non-success), все действия
= fix-a, address = (symptom=a, ctx=absent) — константа серии.

Пороги K ∈ {1,2,3,4,5,6}: переход на эпизоде N(K) = первый i, где
outcomes[i-K+1..i] все non-success (без success между ними).
- noise-серии: N(K) — первый K-run (ложный переход);
- stale-серии: N(K) — первый K-run ПОСЛЕ t0=30 (до t0 — шумовые
  K-run'ы не считаются; пропуск = «перехода нет до конца»).

Фоновая статистика (измерение): фон(t) = доля non-success среди
последних W=15 эпизодов до t (скользящая; только последствия).

## 3. Метрики и порядок

1. Сырые серии (outcome-строки) — смотрим первыми.
2. Распределения времён перехода N(K) по ячейкам (повторы
   объединяются): noise vs stale при ОДНОМ И ТОМ ЖЕ фоне;
   для каждого K: разделение (пересечение распределений; если
   пересечение пусто/мало — разделяются).
3. Hold-out: правила фиксированы выше; серии делятся: первые 30
   эпизодов (train-часть: для noise — весь «фон»; для stale —
   до t0) / последние 30 (hold-out: для stale — после t0).
   Устойчивость разделения проверяется на hold-out-половинах
   (для noise: сравнение N(K) на 1-30 vs 31-60 — шум стационарен;
   для stale: K-run'ы в 31-60).
4. Выбор ветки:
   - (A) при каждом фоне распределения noise/stale не разделяются
     (пересечение > 0 и существенно) → фон адаптирует стоимость;
   - (B) при фиксированном фоне распределения разделяются
     устойчиво (hold-out) → история среды = доп. канал;
   - (C) существует режим фона (ожидание: high, p=0.35 и/или
     p→1-экстраполяция), где распределения сходятся к
     неразличимым → сильная информационная граница.
   B засчитывается только при устойчивости на hold-out.

## 4. Запреты (протокольные)

- v0.5 не изменяется; в эпизодах НЕ исполняется exploration/
  переходов (если v0.5 вдруг вернёт exploration в эпизоде —
  регистрируется как событие-аномалия, действие НЕ выполняется
  (фиксированный fix-a));
- никаких trust-чисел; фон — только последствия (без envfact);
- seed-ы и параметры не меняются после старта; повтор серии при
  сбое — целиком;
- интерпретация A/B/C — только после полной матрицы и hold-out.
