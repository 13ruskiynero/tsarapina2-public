## 1. Вопрос (формулировка профессора)

> Когда накопленная история последствий становится достаточным
> основанием перестать эксплуатировать exact-знание и перейти к
> проверке/исследованию, сохраняя noise robustness?

Узкая проверяемая версия (по событию-кандидату из STALE-EXACT-2):
> Достаточно ли события «второй последовательный non-success той
> же (symptom, context, command)» для БЕЗОПАСНОГО перехода
> S2 → исследование, и не ломает ли такой переход доказанные
> свойства v0.4?

НЕ «как чинить stale»; НЕ интеграция 2×failure в основную
Strategy (скачок «сигнал → механизм» запрещён). Эксперимент:
механика перехода ТОЛЬКО в experimental-ветке; проверяется
достаточность и цена.

## 2. Механика-кандидат (experimental; v0.4 не меняется)

Событие E2(a): 2-й ПОСЛЕДОВАТЕЛЬНЫЙ non-success эпизода с тем же
(адрес: symptom+ctx; та же команда exact-знания). Событие
СТРУКТУРНОЕ (привязано к адресно-командной истории), не
глобальный счётчик «N failure»: failure другого адреса/команды
счёт не пополняет.

Переход: при событии E2(a) suggestion получает exploration=True →
контур исполняет систематический перебор (SEB-механика, BIN с
fix-aq) до устойчивого success; найденное действие → learn-эпизод
(обычный update) → последующие эпизоды: S2 по адресу (новое знание
того же адреса — recency внутри eligible, v0.4).

Активация механики — по событию; вне события выбор = v0.4
полностью (тот же код путей: exact-eligible/recency-tiebreak,
SEB-отсутствие exact, S3-конфликт, legacy без ctx).

## 3. Контроли и серии (тот же полигон B: w1=[a], w2=[a,q],
noise=[a,n]; q/n скрыты; адрес (a, absent) во всех мирах)

1. **baseline-properties (регрессия на контуре с механикой)**:
   known A 1 действие; AB fix-ab; SEB-C (нет exact → exploration →
   fix-c); S3 объявленного конфликта; swap; determinism; legacy-
   знание без ctx (не отбрасывается). Требование: механика НЕ
   меняет эти пути (событие не возникает: не-success нет или не
   последовательные).
2. **single-noise** (w1, s,s,noise-f,s,s): перехода нет (событие
   не собрано); цена шума = 1 лишнее действие (как v0.4).
3. **stale** (learn w1; w2 ×6): первый f — неопределённость (нет
   перехода); ВТОРОЙ f — событие → exploration → перебор →
   fix-aq (success) → последующие эпизоды S2 fix-aq (1 действие).
   Измерение: число действий до восстановления (ожидание: 1-й f
   (1 действ.) + 2-й f (1 действ.) + перебор до fix-aq (позиция
   fix-aq в BIN) + восстановленный эпизод 1 действ.).
4. **double-noise** (w1 ×2, noise ×2 подряд, w1 ×3): ложное
   срабатывание события (2 шумовых f подряд) → переход → перебор
   находит fix-a (мир w1!) → возврат S2 fix-a. Измерение: цена
   ложного перехода (действия перебора), отсутствие повреждения
   знаний (fix-a остаётся; история цела; provenance цел).
5. **alternating** (w1, noise, w1, noise, w1 ×2): события нет
   (f не последовательные) — 0 переходов.
6. **mix** (w1 s, noise f, w1 s, w2 f,f,f): первый w2-f — нет
   перехода (предшествует s); второй w2-f — событие → exploration
   → fix-aq → восстановление. Задержка после смены мира = 1 эпизод
   (граница первого эпизода сохраняется: переход не «предсказывает»
   смену, а реагирует на её второе последствие).

## 4. Метрики и критерии

M1 восстановление: stale-серия: после события ≤ K действий до
устойчивого success (K = длина перебора до fix-aq, фиксируется
до прогона по BIN-позиции).
M2 noise-robustness: single-noise: 0 переходов; double-noise:
ложный переход ≤ 1, цена зафиксирована (действия), знания целы
(версии/provenance), последующие эпизоды S2 fix-a.
M3 свойства v0.4: все baseline-properties PASS на контуре с
механикой.
M4 событие: срабатывает ТОЛЬКО на 2-м последовательном f того же
(адрес, команда); 0 срабатываний на единичных f; 0 на f разных
команд/адресов (серия: чередование fix-a-f / fix-a2-f? — если
не-success разных команд не суммируется).

**PASS:** M1–M4 выполнены → событие f,f достаточно для
безопасного перехода при цене ложного срабатывания ≤ измеренной
(double-noise) и сохранении свойств v0.4; формулировка: «второй
последовательный non-success при совпадающем адресе достаточен
для перехода exact → исследование в данном полигоне; цена —
ложный переход на двойном шуме (измерена), граница первого
эпизода сохранена».
**BOUNDARY/FAIL:** если M1/M2/M3/M4 не выполняются — фиксируем
границу (например: событие достаточно, но цена ложного перехода
неприемлема; или переход ломает свойства; или событие не
воспроизводится на контуре) — без расширения механики.
