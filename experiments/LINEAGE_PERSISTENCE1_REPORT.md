## 1. Вопрос и ветки (как DESIGN, кратко)

> Какая семантика lineage должна сохранять приобретённую
> applicability-структуру через промежуточное failure-знание?

F0 = v0.6 baseline (контроль воспроизводимости AB-1); F1 = field-
bearing pivot (pivot — последний член prior с applicable_when);
F2 = failure-excluded lineage (знания по не-success опыту не входят
в prior_lineage). Главный критерий (ревью профессора): **reopened ==
0** — версия с V ∈ applicable_when, созданная при prior С field-
bearing членами, но pivot без поля; honest (V в Q1-срезе при prior
без field-bearing членов) — норма, не дефект; mech_reopen (путь
кода reopen без fb-членов, результат ≡ honest) — регистр, не дефект.

## 2. Результаты (r1; r2 идентичен)

```
ветка   S0         S1         S2         S3         S4         S5
       re/h/m/lv  re/h/m/lv  re/h/m/lv  re/h/m/lv  re/h/m/lv  re/h/m
F0     0/1/0/PASS 1/1/0/FAIL 0/1/1/PASS 1/1/0/FAIL 1/1/0/FAIL 0/1/1
F1     0/1/0/PASS 0/1/0/PASS 0/1/0/PASS 0/1/0/PASS 0/1/0/PASS 0/1/0
F2     0/1/0/PASS 0/1/0/PASS 0/1/0/PASS 0/1/0/PASS 0/1/0/PASS 0/1/0
```

re = reopened; h = honest (V-версии); m = mech_reopen; lv = latest-
уровень (S0–S4; S5 — состояние). Latest-версия линии (a, absent,
fix-a):

- F0 S1/S3/S4: {E:absent, V:2}, obs ∅ — reopened=1, latest FAIL
  (воспроизведение AB-1);
- F0 S0/S2: {E:absent} + obs V[1,2] disagreement — PASS;
- F1/F2 S0–S4: {E:absent} + obs V[1,2] — PASS, reopened=0;
- S5 во всех ветках: {E:absent, V:2} — honest snapshot (предел:
  до двух расходящихся success нет инварианта для сохранения).

## 3. Регистры и что они показали

**F0 = AB-1 воспроизведён + новые контроли.** S1/S3/S4: wY-знание
после noise создано при pivot без поля при существовавшей структуре
(w1-знание с полем) → reopened, latest переоткрыт. S2: w1-шаг —
mech_reopen=1 (pivot = noise без поля, fb-членов нет): результат
{ E:absent, V:1} идентичен honest-срезу (подтверждено примечание
профессора: «честный первый acquisition после failure»); wY-шаг —
восстановление через w1-знание с полем → latest PASS. S0-контроль:
honest=1 — V в Q1-срезе первого success есть и в failure-free
базисе (буквальный полный критерий AB-1 «V ∉ aw по всему стору»
падает уже на S0 — след декомпозирован: honest ≠ reopened).

**F1 и F2 = reopened 0 на всех 24 прогонах.** После failure следующий
success переносит инвариант от последнего field-bearing знания:
latest {E:absent} + obs V[1,2]. Honest-след (V в Q1-срезах) сохранён
в обеих ветках — это норма, а не failure-артефакт. Путь reopen в
F1/F2 не запускался ни разу (mech=0): pivot либо отсутствовал, либо
нёс поле. Failure-знания остаются в сторе (append-only) во всех
ветках — exclusion касается только выбора prior, не хранения.

**Лемма 2.1 подтверждена: F1 ≡ F2** на всех 6 последовательностях ×
2 реплики (нормализованные отпечатки идентичны). В текущем полигоне
aw=None ⟺ не-success для членов линии, поэтому фильтры F1 и F2
выбирают один и тот же prior. Выбор между F1 и F2 **не является
эмпирически разрешимым в LP-1** — это две разные модели истории
(F1: failure — член перечисления lineage, но не pivot; F2: failure
вне prior_lineage), и различие станет наблюдаемым только вне
полигона (член линии с aw=None, не являющийся failure, либо
failure-член с наблюдениями).

## 4. Корригенда к AB-1 §3 (интерпретация eligibility-проб)

В AB-1 knowledge_refs проб печатались без applicable_when, и §3
отчёта AB-1 интерпретировал выбор пробы w1 в S1/S3/S4 как «СТАРОЕ
знание с узким условием {E:absent,V:1} — компенсация историей».
LP-1 регистрировал aw каждого выбранного знания: **эта
интерпретация не подтвердилась.** В F0 S1/S3/S4 проба w1 (и noise)
выбирает знание с aw=None — это failure-знание (noise, вердикт
partial), адресуемое через legacy-путь v0.5 (знание без поля
проверяется по ctx, а не по наблюдениям); старое узкое w1-знание
{E:absent,V:1} при этом в сторе есть, но не выбирается (recency:
noise-знание новее). Проба wY выбирает свежайшее {E:absent,V:2}.
Следствие §3 «при retract старого знания задача w1 получит S3»
также не подтверждается: выбор w1-пробы держится на noise-знании.

Вердикт AB-1 (latest-уровень + регистры стора) от этого НЕ зависит —
он измерен структурно. Уточняется только объяснение «почему система
выглядит здоровой»: поведенческая корректность в F0 держится в том
числе на legacy-пути v0.6, который делает failure-знание адресуемым
как known_fix. Это усиливает вывод профессора: поведенческий тест
недостаточен, и selected knowledge_id со структурой (aw) — правильное
измерение (в AB-1 без aw ошибка была невидима).

Пробы в F1/F2: все три мира выбирают СВЕЖАЙШЕЕ широкое знание
{E:absent}+obs (w1-проба больше не уходит ни в failure-знание, ни в
старое узкое). Поведение всюду S2 fix-a — ветки неразличимы
поведенчески и различимы по selected knowledge_id (как предсказано
дизайном, с уточнением F0-стороны по корригенде).

## 5. Вердикт

**LP-1: обе операционализации persistence (F1 field-bearing pivot,
F2 failure-excluded lineage) восстанавливают перенос приобретённой
applicability-структуры через промежуточное failure-знание на
S1–S4: reopened = 0, latest {E:absent} + obs V[1,2], поведение
S2 fix-a без изменений; honest-след Q1 сохранён; failure-знания не
теряются (append-only, опыт-цепочка цела).**

- F0-контроль воспроизвёл AB-1 и добавил недостающие базы: S0
  (failure-free: honest-след V существует и без failure — полный
  критерий AB-1 недефектно падает) и S5 (предел: honest snapshot во
  всех ветках — «сохранять структуру там, где она не приобреталась»
  не происходит ни в одной ветке).
- **F1 ≡ F2 подтверждена** — выбор между ними не эмпирически
  разрешим в текущем полигоне; открыт архитектурный вопрос (две
  модели истории; различие наблюдаемо вне полигона).
- Watch «информационная значимость failure»: в текущем полигоне
  failure-запись структурно бедна (нет поля, нет D2-наблюдений) —
  ни F1, ни F2 сигнал не теряют; семантическая проверка требует
  варианта записи failure-наблюдений — open question вне core-grid.
- v0.6 остаётся FROZEN. «Победитель» между F1/F2 НЕ назначается —
  слово профессора (архитектурное решение либо discriminating-
  сценарий отдельным экспериментом).
