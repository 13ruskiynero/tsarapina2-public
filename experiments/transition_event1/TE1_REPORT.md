# TSARAPINA TRANSITION-EVENT-1: ОТЧЁТ (06.09.2026)

Дизайн: TRANSITION_EVENT1_DESIGN.md (frozen). Ветка:
transition_event1/strategy_v7.py (v0.4 + E2-переход; основная
Strategy v0.4 НЕ изменялась). Прогон: te1_driver.py (parts:
base/stale/noise/m4; TE1_*_run.txt + TE1_run.log). Критерии M1–M4
зафиксированы в дизайне ДО прогона. Порядок: сырые траектории →
событие → восстановление → noise → остальное.

## 1. Определение события (по дизайну, операционально)

E2(addr, cmd): два ПОСЛЕДНИХ знания (addr, cmd) — non-success
(история из Knowledge: знания update/rule; успех сбрасывает
последовательность; не-success других команд/адресов не
накапливается). Событие видно на РЕШЕНИИ, следующем за вторым
не-success (задержка от момента накопления = 1 эпизод).

## 2. Сырые траектории

**BASE (свойства v0.4 на контуре с механикой):**
- KNOWN: learn fix-a → эпизод: S2 fix-a, 1 действие, success;
- AB: learn fix-ab (мир ab) → S2 fix-ab, 1 действие;
- SEBC: C без знания: гипотеза fix-b (broad) → partial → раунд
  exploration (S1+insufficiency) → перебор: start/restart/fix-a/
  fix-b/fix-ab/fix-a2/fix-aq fail → **fix-c success (9 действий)**;
  затем C2: S2 fix-c, 1 действие (SEB-механика intact);
- S3: объявленный конфликт (s/f) → S3 (не разрешён молча);
- DET: повторный suggest идентичен.
→ M1 (базовые свойства) ПРОЙДЕН.

**STALE (learn fix-a в w1; мир сменён на w2=a+q):**
- st_f1: S2 fix-a → partial (история: 1 не-success — события нет);
- st_f2: S2 fix-a → partial (последние знания [f1, learn-s] —
  события нет);
- st_f3: последние знания [f2, f1] — **E2-СОБЫТИЕ** →
  SEB-перебор: start/restart/fix-a/fix-b/fix-ab/fix-a2 fail →
  **fix-aq success (7 действий перебора)**;
- st_f4, st_f5: S2 fix-aq, 1 действие (знание зафиксировано).
→ M3 (переход на устаревании → recovery) ПРОЙДЕН. Цена от смены
мира: 2×S2-failure + 7 шагов перебора = 9 действий; далее S2 по
1 действию.

**NOISE:**
- SINGLE (s,s,f,s,s): 0 переходов → M2 (шум-инвариантность
  одиночного шума) ПРОЙДЕН;
- ALT (s,f,s,f,s,s): 0 переходов (чередование не накапливает
  f,f);
- DOUBLE (s,s,f,f,s,s,s): nd_f1, nd_f2 (двойной шум) → nd_s3:
  **ЛОЖНЫЙ ПЕРЕХОД** → перебор: start/restart fail, **fix-a
  success (3 действия)**; nd_s4/s5: S2 fix-a, 1 действие (знание
  восстановлено, не разрушено) → M4 (ложное срабатывание с
  измеренной ценой) — цена: +2 действия (3 вместо 1), полное
  восстановление;
- MIX (s, noise-f, s, w2-f1, w2-f2, w2-f3, s): noise-f не
  триггерит; w2-f1: нет (после s2); w2-f2: нет (последние [f1,
  s2]); w2-f3: последние [f2, f1] — **переход** → перебор 7
  действий → fix-aq success; затем S2 1 действие. Задержка от
  накопления = 1 эпизод (как STALE); шумовая история не
  ускоряет/не замедляет событие.

**M4 (не-success разных команд не суммируются):**
- fix-a: 1 не-success + fix-b: 1 не-success (тот же адрес) →
  события НЕТ (S2, transition=false). Структурность события
  подтверждена: счёт не глобальный.

## 3. Итог по критериям (зафиксированы до прогона)

- M1 базовые свойства v0.4 на контуре с механикой: PASS
  (KNOWN/AB/SEBC/SEBC2/S3/DET — все как v0.4);
- M2 single-noise: 0 переходов: PASS;
- M3 stale: переход на 2-м накопленном не-success → перебор →
  fix-aq → S2 по 1 действию: PASS (9 действий от смены мира до
  первого успеха);
- M4 double-noise: ложный переход: измерено (+2 действия на
  эпизоде перехода; знание и S2-работа восстановлены полностью):
  PASS-граница: двойной шум неотличим от устаревания по событию
  (это ожидаемая цена: событие «2 не-success подряд» не различает
  источник — как и предсказано STALE-EXACT-1/ES-1; различие
  остаётся информационным, событие — не «детектор устаревания»,
  а «достаточное накопление для безопасного перехода» с
  известной ценой ложного срабатывания);
- ALT/MIX: чередование 0 переходов; MIX: задержка 1 эпизод от
  накопления, шум не ускоряет/не замедляет;
- M4-структурность: разные команды не суммируются: PASS.

## 4. Вердикт (формулировка)

**TE-1: PASS — событие «2-й последовательный non-success того же
(адрес, команда)» достаточно для безопасного перехода
S2 → exploration в данном полигоне.** Достигнуто: (1) stale
восстанавливается (переход → систематический поиск → fix-aq →
S2 по 1 действию); (2) одиночный шум и чередование не триггерят
переход (шум-инвариантность сохранена для одиночных сбоев); (3)
двойной шум даёт ложный переход с ЯВНО измеренной ценой (+2
действия) и полным сохранением знания (v0.4-эксплуатация после
восстановления); (4) событие структурно (адрес+команда), разные
команды не суммируются; (5) свойства v0.4 (S2 exact, S3-конфликт,
SEB-отсутствие-знания, детерминизм) не нарушены.

**Цена и граница:** событие НЕ различает источник второго
не-success (устаревание vs двойной шум) — это информационная
граница, установленная ES-1/STALE-EXACT-1/SE2; переход по событию
безопасен в смысле «знание не разрушается и эксплуатация
восстанавливается», но несёт ложные срабатывания на двойных
сбоях (измерено: 1 эпизод по 3 действия вместо 1). Механика
остаётся в ветке strategy_v7: интеграция в основную v0.4 — по
решению профессора (урок: PASS ветки ≠ авто-интеграция;
STALE-EXACT-2: «сигнал → механизм» без гейта запрещён).
