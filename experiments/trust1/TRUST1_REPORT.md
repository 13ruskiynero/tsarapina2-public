## Результаты (изолированные сценарии; детерминизм: да у всех)

```
механизм   S1      S2      S3       S4      S5      S6a/S6b
base       loop(6) fix-a(1) loop(6)  fix-a(1) loop(6)  loop/fix-a2(1)
T1         S3(0)   S3(0)   loop(6)  S3(0)   S3(1)    S3/S3(0)
T1+T2      S3(0)   S3(0)   fix-a(1) S3(0)   S3(1)    S3/S3(0)
T1+T2+T3   S3(0)   fix-a(1) fix-a(1) fix-a(1) fix-a(1) S3(1)/fix-a2(1)
```
- S1 (s→f→задача, правильного нет): base — петля; T1+ — S3-стоп.
- S2 (s,f,s → возврат к fix-a): base/T1+T2+T3 — fix-a; T1, T1+T2 —
  S3-БЛОКИРОВКА возврата (auto-conflict висит несмотря на свежий
  success).
- S3 (fix-a s + fix-b f): base/T1 — петля (recency на свежий
  failure); T1+T2 и T1+T2+T3 — fix-a.
- S4 (шум: s,f,s): base/T1+T2+T3 — fix-a; T1/T1+T2 — блок.
- S5 (evidence: agg 3×fix-a vs fix-b): base — петля; T1/T1+T2 —
  одна неверная попытка fix-b → S3; T1+T2+T3 — fix-a (свидетельства
  3 > 1).
- S6 (устаревание): T1+T2+T3: S6a S3(1) — одна проверка fix-a →
  failure → конфликт → стоп (не петля); S6b fix-a2(1) — после learn.
  base: S6a петля; T1/T1+T2: S6b S3 (блок после learn fix-a2).

## Результаты «одна жизнь» (накопление; реалистичный L1-контекст)

```
механизм    accS1    accS2    accS3    accS5    accS6b
base        loop(6)  fix-a(1) loop(6)  loop(6)  fix-a2(1)
T1          S3(0)    S3(0)    S3(0)    S3(0)    S3(0)
T1+T2       S3(0)    S3(0)    S3(0)    S3(0)    S3(0)
T1+T2+T3    S3(0)    fix-a(1) fix-a(1) fix-a(1) loop(6)
```
Ключевое: T1+T2+T3 в НАКОПЛЕННОЙ истории: accS1–accS5 — PASS, но
accS6b — loop(6): после learn fix-a2 контур продолжает выбирать
fix-a (накопленные успехи: агрегат evidence=3 + исторические s
перевешивают свежие провалы) и за 6 действий не переключается.
**Свежие свидетельства проигрывают старым агрегатам.**

## Вердикт

**PARTIAL с границей (не PASS, не FAIL):**

1. T1 (auto-conflict) соло и T1+T2: чинят S1 (стоп), но ЛОМАЮТ
   возврат после свежего успеха (S2/S4/S6b → S3-блок): механическое
   фиксирование противоречия без разрешения не пригодно как
   автономный механизм.
2. T1+T2+T3 проходит ВСЕ изолированные сценарии S1–S6, но падает в
   накопленной истории на устаревании (accS6b): evidence-правило
   перевешивает свежие проверенные провалы старым накопленным
   успехом (агрегат 3 эпизодов + история > 2-3 свежих failure).
3. Ни одна комбинация не даёт полного PASS в «одной жизни».

**Это ровно гипотеза-граница дизайна:** механические правила выбора
при конфликте не проходят реалистичный контроль (накопление +
устаревание). Причинного слоя у контура нет (почему fix-a вдруг
перестал работать — невидимо), и никакое взвешивание прошлых
свидетельств не может отличить «шум» от «среда изменилась» без
новых проверенных последствий. Вывод зоны 3 (по дизайну):

> **Разрешение конфликтов = цикл новых проверенных последствий,
> а не вычисление доверия. Trust-число не строится (и не должно
> строиться). S3-остановка остаётся единственным механизмом
> конфликтной защиты; после S3 контур ждёт нового проверенного
> эпизода (learn оператора/мира), а не «решает» по числам.**

T1/T2/T3 НЕ интегрируются в основную Strategy (как и предусмотрено:
без полного факторного прогона; прогон выполнен — результат
отрицательный для интеграции в накопленном сценарии). strategy_v3
остаётся экспериментальной веткой; auto_conflict (T1) — полезен
как ручной/контурный инструмент фиксации противоречий (не выбор).
