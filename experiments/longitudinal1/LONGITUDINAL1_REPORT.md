Прогон по замороженному протоколу (FREEZE). 58 эпизодов: E1–E50 +
UA1–UA6 + SW1–SW2. Модель неизменна (gemma3:4b; qwen2.5:3b — только
swap-контроль). Архитектура не менялась; дефекты не чинились.

## Технические оговорки (прозрачность данных)

- **run-1 INVALID** (архив: data_*_INVALID_run1, LONGITUDINAL1_
  run1_INVALID.log): дефект реализации среды: `rm /run/tsasvc.lock.*`
  и `ls /run/tsasvc.lock.*` в subprocess без shell — glob не
  раскрывается → флаги накапливались (мир с E21 ≠ протокольный),
  сенсор симптома всегда возвращал «none» (все problem-строки
  неразличимы). Исправлено (явное удаление через glob в Python;
  сенсор — glob), плюс created_at знания переведён на микросекунды
  (секундная гранулярность давала tie в выборе «самого свежего»
  знания S2 — артефакт измерения, не изменение правил). Прогон
  повторён с нуля: **run-2 — валидный**.
- **UA-фаза технически остановлена на UA2** (дефект фильтра:
  «НЕ перевело» содержит подстроку «перевело» → k_old == k_fail,
  declare_conflict «сам с собой»); фильтр исправлен, UA2–UA6+SW
  продолжены на том же сторе (resume_ua.py). E1–E50 run-2 не
  затронуты.

## Гипотезы (по FREEZE-списку)

- **H-L1 накопление: ПОДТВЕРЖДЕНА.** После learn-показа класс
  решается через S2 (детерминированно, без LLM), 1 действие:
  A 8/8, B 8/8, AB 8/8. Модель не менялась.
- **H-L2 накопительная эффективность: ЧАСТИЧНО.** На решаемых
  классах redundant_actions = 0, actions_to_success = 1 (минимум)
  от первого до последнего эпизода. НО «эффективность относительно
  собственной истории» обрывается возвратом старого класса (см.
  H-L3): класс не «дешевеет», а перестаёт решаться.
- **H-L3 (открытый исход реализовался): ПОДТВЕРЖДЕН КАК ДЕФЕКТ.**
  Возврат A после обучения B: S2 выбирает самое свежее релевантное
  знание (фиксирующий матчинг ≥1 общего токена) → fix-b к A →
  partial → 0/3. **Граница Strategy: выбор знания не контекстно-
  специфичен; знание о неудаче (fix-b «НЕ перевело» для A) тоже
  содержит fix-b и не спасает — контур не переходит к исследованию
  (S1).** НЕ чинилось (карантин).
- **H-L4 комбинации: learn-AB → S2 → 8/8.** «Перенос» AB без
  показа в раскладке не тестировался (по протоколу AB-эпизоды
  идут после learn-AB).
- **H-L5 новые ситуации: ПОДТВЕРЖДЕНА (граница).** C (никогда не
  показывалась): tsar 0/7, bare 0/3. Контур применяет к C чужие
  знания (S2: свежайшее fix-* из A/B/AB-серий) вместо перехода к
  исследованию → failure. **Приобретение ≠ обобщение; широкий
  матчинг мешает даже S1-исследованию.** «external memory ≠
  generalization» — граница механизма зафиксирована.
- **H-L6 устаревание: ПОДТВЕРЖДЕНА.** K_old → failure → K_fail →
  declare_conflict → **S3: контур НЕ повторил устаревшее действие
  вслепую** (UA3; LLM-перебор start/restart не привёл к успеху —
  это НЕ «автоматическое исправление») → learn fix-a2 → retract
  (аудит) → S2 fix-a2 (UA6). История проверенных утверждений
  выдерживает противоречивый мир: старые версии не стёрты.
- **H-L7 knowledge-рост: ПОДТВЕРЖДЕНА (отрицательный сигнал).**
  47 записей ≈ числу tsar-эпизодов; десятки дубликатов «fix-b НЕ
  перевело» (один класс) — внешняя память разрастается без
  агрегации; каждая неудача добавляет запись, которая становится
  «свежайшей» и закрепляет неверный выбор (частично усиливает
  H-L3/H-L5-петлю). Агрегация Experience→Knowledge — RESEARCHABLE,
  НЕ чинилась.
- **M6 bare-контроль: bare 0/9** на всех невыводимых классах
  (a/b/ab/c) — «рука» и «линейка» общие, различие — только контур.
- **M7 swap: ПОДТВЕРЖДЕН.** qwen2.5:3b после накопления: S2 → fix-a2
  → success 2/2. Знание принадлежит контуру, не модели.
