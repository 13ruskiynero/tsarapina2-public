# TSARAPINA RELEVANCE-1: ДИЗАЙН (черновик на заморозку, 06.09.2026)

**Статус: НЕ ЗАМОРОЖЕН. НЕ ЗАПУСКАТЬ до слова профессора.**
Первая зона Layer C (порядок профессора). Рабочая Strategy и
протоколы VERTICAL/LONGITUDINAL НЕ меняются: исследование идёт на
отдельном варианте механики выбора (strategy_v2, изолированный
модуль), сравнение — тот же полигон, те же определения/метрики.

## Вопрос

> Может ли Strategy выбирать правильное знание среди нескольких
> одновременно релевантных, не ломая остальные свойства контура
> (приобретение 8/8, S3-защита, swap, детерминизм)?

Данные LONGITUDINAL-1 показали: проблема не «память плохая», а
**«память + контекстно-слепая релевантность создают систематическую
ошибку»**. Изолируем механику выбора.

## Диагноз (что именно ломается в текущей механике)

1. Релевантность: ≥1 общий токен problem → знания всех классов
   tsasvc релевантны любой задаче (общие токены tsasvc/service/
   inactive/symptom гарантированы);
2. Выбор: самое свежее по created_at (recency);
3. Следствие: возврат A после обучения B → fix-b; знания-неудачи
   (fix-b «НЕ перевело» для A) тоже несут fix-b и при recency
   закрепляют петлю.

## Компоненты механики (кандидаты; проверяются РАЗДЕЛЬНО и в
комбинации, на одном и том же полигоне и метриках)

- **R1 symptom-match**: приоритет знаниям, чей опыт problem
  содержит фактические токены состояния (symptom=a) задачи; при
  отсутствии точного — существующий широкий матчинг (fallback);
- **R2 no-failure-action**: знания «НЕ перевело» (failure-исходы)
  НЕ порождают S2-кандидатов (знание неудачи говорит «X не
  работает», но не говорит «делай X»); recency — только среди
  применимых (success/active);
- **R3 recency-внутри-класса**: при нескольких релевантных классах
  — свежайшее ВНУТРИ класса с наибольшим числом/долей успехов
  (простейший счётчик подтверждений, БЕЗ вычисления trust);
- комбинации: R1, R1+R2, R1+R2+R3 (факторно, как в FR-0: понять,
  что несёт эффект).

Правило: R1/R2/R3 — детерминированные, полностью наблюдаемые,
без LLM и без «обучения» (механика, не trust-модель; trust —
зона 3).

## Полигон и прогон (тот же tsasvc, та же раскладка-ядро)

Ядро-сценарий повторяет Longitudinal-1 в миниатюре (валидный
run-2 как эталон):
```
learn-A; tsar A x3; learn-B; tsar B x3;
ВОЗВРАТ: tsar A x3   <- главный тест (эталон: 0/3)
learn-AB; tsar AB x3;
UA-мини: failure → conflict → S3 → learn fix-a2 → retract → S2
swap x2 (qwen25)
bare-контроль на возврате A
```
Метрики: M1 success; M2 actions_to_success; M4 S2-рефы (какие
знания выбраны); детерминизм (повтор того же сценария с тем же
механизмом → тот же выбор); M8 UA-шаги.

## Критерии (заранее)

- НЕ СЛОМАТЬ: learn → A/B/AB 8/8 (1 действие, S2); S3-защита
  сохраняется (UA-мини); swap 2/2; knowledge-рост прежний
  (update не меняется в этом эксперименте);
- ПОЧИНИТЬ (цель): возврат A после B > 0 (цель 3/3);
- если ни одна комбинация не чинит возврат, не ломая остального —
  фиксируется граница механики выбора (отрицательный результат
  зоны 1, переход к зоне 2/3).

## Защиты

- вариант механики — отдельный модуль strategy_v2 (рабочий
  strategy.py не трогается; тесты 19/19 остаются эталоном);
- те же определения (outcome/success), та же «рука» (executor),
  та же «линейка» (evaluation);
- среда: исправленная (явный glob; симптом-сенсор) — как в run-2;
- прогон каждой комбинации не интерпретируется до завершения всех
  комбинаций факторной сетки.
