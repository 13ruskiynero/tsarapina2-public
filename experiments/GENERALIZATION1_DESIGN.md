# TSARAPINA GENERALIZATION-1 / ЗОНА 4: ДИЗАЙН (06.09.2026)

**Статус: ДИЗАЙН на заморозку. Код за воротами до фиксации.**

## 1. Вопрос (дословно, профессор)

> Может ли система получить успешное решение для нового случая C
> из нескольких ранее проверенных случаев A/B, если прямого знания
> C → action в Knowledge нет, при этом новое решение не было
> заранее закодировано ни в Strategy, ни в Knowledge, ни в LLM
> prompt?

**Главное правило зоны 4: НИКАКИХ заранее встроенных правил
переноса** — иначе обобщение окажется положенным в Strategy, а мы
обнаружим его в результате. Никаких similarity-эвристик, аналогий,
«расстояний между симптомами» — ничего, что переносило бы знание
A на C по заранее заданному критерию.

## 2. Что НЕ является переносом (закрытые альтернативы)

Успех C засчитывается как перенос ТОЛЬКО если закрыты все четыре
альтернативы происхождения:

1. **LLM «и так знала ответ»**: предтест на голой LLM (без истории,
   без знаний): если LLM называет fix-c без подсказки — среда
   невалидна (fix-c обязан быть вне словаря модели: полигонные
   команды, как tsafix/fix-* в L1/VERTICAL);
2. **правило заранее в Strategy**: аудит Strategy-кода и rationale
   ДО прогона (замороженный файл + хэш): никаких переносных правил;
   S2 выбирает строго по (симптом-exact → recency) из проверенных
   знаний; S5 передаёт LLM только наблюдения C и общие команды
   (start/stop/restart/диагностика) — fix-* в промпт НЕ попадают;
3. **случайная попытка → повезло**: контроль перебора — baseline,
   который систематически пробует все разрешённые команды
   (включая fix-*) на C: если перебор находит fix-c, «успех
   перебором» ≠ перенос; сравниваем стоимость контура С ИСТОРИЕЙ
   против перебора БЕЗ истории;
4. **прямое знание C в Knowledge**: аудит Knowledge ДО прогона C:
   нет записей с симптомом c (проверка автоматическая).

## 3. Среда (полигон LONGITUDINAL-1, без изменений механики)

- симптомы a (lock.a; fix-a), b (lock.b; fix-b), ab (a+b; fix-ab),
  c (lock.c; fix-c — СУЩЕСТВУЕТ в allowlist, НЕ в Knowledge до
  прогона C, НЕ в промпте LLM);
- fix-* команды разрешены Executor'ом (мир позволяет их
  применить), но ни одна из них не упоминается в задаче LLM;
- контур: Strategy v0.2 + R1 (заморожены), Knowledge/Update/
  Evaluation не меняются; LLM — gemma (qwen25 — swap-контроль);
- эпизоды как в L1: learn (оператор показывает fix), task
  (контур действует; мир отвечает по правилу: действие == fix-X →
  success).

## 4. Процедура (фиксируется до прогона)

**Фаза 1 — обучение A/B (валидность контура):**
learn-a → tsar решает a ×2 → learn-b → tsar решает b ×2 →
learn-ab → tsar решает ab ×2. Ожидание: S2, fix-a/fix-b/fix-ab,
все success (контур работает; знания A/B/AB в History).
Стоп-критерий: если контур не решает a/b/ab — прогон невалиден.

**Фаза 2 — предтест LLM (закрыть альтернативу 1):**
голая LLM (gemma), задача C (текст: симптом c; доступные команды
— только общие): предлагает ли fix-c? Предтест: 3 запроса.
Критерий: НИ ОДИН ответ не содержит fix-c (и его не знает ни
одна модель, включая qwen25) — иначе среда невалидна (fix-c не
является «новым решением»).

**Фаза 3 — C без прямого знания (7 эпизодов, как H-L5):**
tsar-контур (история A/B/AB), симптом c, БЕЗ learn. Мир отвечает
по правилу (fix-c → success, всё остальное → failure). Измеряем
каждый эпизод: стратегия, действия, исходы. 7 эпизодов (H-L5-канон).

**Фаза 4 — контроли (на чистых сторах):**
- 4a bare: голая LLM без истории, 7 эпизодов C (тот же промпт);
- 4b перебор: систематический перебор разрешённых команд
  (start/restart/fix-a/fix-b/fix-ab/fix-c/...) с проверкой, до
  первого success (макс 12 шагов на эпизод), 7 эпизодов;
- 4c sanity: tsar + learn-c (один показ) → эпизод C: ожидание S2
  fix-c success (среда и механика валидны; «прямой опыт создаёт
  знание» — контроль-фонарик);
- 4d swap: qwen25 повтор Фазы 3 (3 эпизода) — независимость от
  модели.

## 5. Метрики (до прогона)

- M1: число успешных эпизодов C из 7 (с историей / bare / перебор);
- M2: actions_to_success на C (или «не решено за MAX»);
- M3: тип предлагаемого действия по эпизодам: из Knowledge (S2),
  от LLM (S5/S1-наблюдение), перебор; rationale-аудит;
- M4: стоимость «знания»: средние действия до отказа от попытки
  для tsar-истории vs bare vs перебор (знание мешает/помогает
  поиску);
- M5: история/версии целы (M3-стандарт всех зон);
- M6: детерминизм (повтор Фазы 3 — тот же профиль).

## 6. Исходы (фиксируются заранее)

- **ПЕРЕНОС ЕСТЬ**: ≥1 эпизод C решён без learn, с действием не из
  A/B-знаний и не из словаря голой LLM, при закрытых альтернативах
  1–4 (тогда — разбор источника: откуда пришло новое действие);
- **ПЕРЕНОСА НЕТ (ожидаемый, по H-L5)**: 0/7; контур применяет
  релевантное A/B-знание → failure; перебор находит fix-c, контур
  с историей — нет (или позже);
- **ЗНАНИЕ БЛОКИРУЕТ ПОИСК**: tsar-история хуже bare/перебора по
  M2/M4 (уверенная привязка к известному мешает открытию нового) —
  уточнение отрицательного результата;
- **КОНТРПРИМЕР СРЕДЫ**: предтест показал fix-c в ответах LLM →
  среда невалидна, дизайн пересматривается (fix-c заменяется на
  команду вне словаря).

Вердикт по формуле профессора: перенос засчитан только при
закрытых альтернативах; ожидаемый результат зоны 4 —
отрицательный, формализующий H-L5: **новое знание (C → action)
возникает только из прямого проверенного последствия C; из A/B
оно не возникает ни через Knowledge, ни через LLM, ни через
Strategy; «обобщение» в этой архитектуре не появляется из ничего
— и это измеряемая граница, а не отсутствие старания.**

## 7. Красные ограничения (НЕ делать)

🔴 правила/эвристики переноса в Strategy (главный запрет);
🔴 similarity/расстояние/«похожесть» симптомов где-либо;
🔴 fix-* в LLM-промпте; подсказки «вспомни как лечили A/B»;
🔴 learn C до Фазы 3 (только 4c после); 🔴 изменение
Knowledge/Update/Evaluation/R1; 🔴 «обобщающий» агрегатор (зона 2
— explicit-инструмент, не трогаем); 🔴 интерпретация до полного
прогона (freeze-дисциплина).
