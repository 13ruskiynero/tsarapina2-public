## 1. Гипотеза (измерена как есть)

failure-знание (без applicable_when) той же линии (a, absent, fix-a)
становится prior[-1] для следующего acquisition → pcond={} →
переоткрытие условия из контекста последнего success.

## 2. Результаты (детерминированы: r1 ≡ r2)

```
последовательность        latest-знание линии          критерий
S1: w1-s noise-p wY-s     {E:absent, V:2}, obs=[]      FAIL
S2: noise-p w1-s wY-s     {E:absent}, obs V[1,2]       latest PASS /
                                                       полный FAIL
S3: w1-s noise-p noise-p wY-s  {E:absent, V:2}, obs=[] FAIL
S4: w1-s w1-s noise-p wY-s     {E:absent, V:2}, obs=[] FAIL
```

- **S1/S3/S4**: гипотеза подтверждена на latest-уровне — после
  failure, вклинившегося после успешного acquisition, следующий
  verified-success переоткрывает условие из своего контекста:
  {E:absent, V:2}; observations V[1,2] потеряны; ACQ-1-инвариант на
  свежайшем знании разрушен.
- **S2** (failure до первого success): latest-знание ВОССТАНОВЛЕНО —
  {E:absent} + obs V[1,2]. Механика (уточнение предсказания дизайна):
  на шаге w1-s prior НЕ пуст (содержит noise-failure той же линии) →
  переоткрытие {E:absent, V:1} у промежуточного w1-знания; на шаге
  wY-s prior[-1] — w1-знание С полем → V-дивергенция срабатывает
  штатно → инвариант восстановлен. Самовосстановление требует ещё
  одного success после версии с полем.
- **Полный критерий (V ∉ applicable_when по всему стору): FAIL ВЕЗДЕ,
  включая S2** — промежуточное w1-знание (созданное после noise)
  несёт V в applicable_when и остаётся в истории (append-only).

## 3. Поведенческие маркеры (eligibility-пробы)

Все пробы во всех последовательностях: S2 fix-a (правильное
поведение сохранено — но по разным причинам):

- S1/S3/S4, проба w1 (V=1): выбран СТАРОЕ знание с узким условием
  {E:absent,V:1} (переоткрытое {E,V2} не eligible при V=1) —
  **компенсация историей**: дефект свежайшей версии скрыт, пока живо
  старое знание; при его retract задача w1 получит S3;
- S1/S3/S4, проба wY (V=2): выбрано переоткрытое {E:absent,V:2};
- S2: пробы w1 и wY выбирают свежайшее корректное знание {E:absent}.
- проба noise: S2-применение (слепота; ожидаемая граница Observer'а).

## 4. Вердикт

**ГИПОТЕЗА ПОДТВЕРЖДЕНА (позиционная форма, latest-уровень):
S1/S3/S4 — latest-знание переоткрыто ({E:absent,V:2}, obs пусто);
S2 — latest восстановлен самовосстановлением на втором success.
ПОЛНЫЙ критерий: FAIL во всех последовательностях — след
V-в-условии остаётся в истории стора при failure в любой позиции.**

**BOUNDARY: приобретённая applicability-структура НЕ является
автоматически устойчивым состоянием lineage при появлении
промежуточного опыта, который сам не содержит applicable-поля.
Граница возникает при восстановлении структуры после уже
существующего успешного acquisition (S1/S3/S4); failure до первого
acquisition тоже оставляет след (V в промежуточной версии, S2),
залечиваемый только следующим success.** Конкретный дефектный
механизм: acquisition переносит инвариант через prior[-1], не
различая знания с applicable_when и без него (failure-знания).

v0.6 остаётся FROZEN. Обработка границы (кандидаты, НЕ решены):
acquisition должен переносить инвариант от последнего знания линии,
НЕСУЩЕГО applicable_when (скипая failure-знания без поля), и/или
failure-знания не входят в prior_lineage для переноса. Решение — по
слову профессора, отдельным шагом.

## 6. Закрытие AB-1 (слово профессора, 07.09.2026)

Профессор: «Это очень хороший boundary. Причём неприятно хороший,
в научном смысле». **AB-1 закрыт как BOUNDARY + локализованный
механизм + два открытых кандидата обработки.** v0.6 остаётся
эталоном (в следующем эксперименте — ветка F0). Разделы 1–5 не
пересматриваются; вердикт раздела 4 подтверждён.

- **Главный содержательный вывод:** поведенческая корректность может
  сохраняться при уже нарушенной внутренней структуре знания.
  Все траектории выглядят правильными через S2 fix-a (eligibility-
  пробы), хотя структура lineage уже различается. Поэтому selected
  knowledge_id и жёсткий критерий (V ∉ applicable_when) были
  правильными измерениями; поведенческий тест недостаточен.
- **Операционная формулировка boundary** (рядом с главной, раздел 4):
  > Lineage persistence currently depends on the position of the
  > latest record, not on preservation of the last verified
  > applicability structure.
  Указывает на объект следующего эксперимента, не превращаясь в
  преждевременное «надо просто исправить функцию».
- **Что НЕ делать:** v0.6 не трогать; между двумя кандидатами не
  выбирать — они пока конкурирующие механизмы исправления, а не
  установленное решение (F1: перенос инварианта от последнего знания
  линии, несущего applicable_when; F2: исключение failure-знаний из
  prior_lineage). Иначе: нашли контрпример, тут же починили код —
  и выяснили, что исправили не то явление.
- **Замечание при закрытии (передано в LP-1; вердикт AB-1 не
  затрагивает):** полный (store-wide) критерий «V ∉ applicable_when
  по всем версиям» имеет ≥2 источника следа V-в-условии — честный
  Q1-срез первого success (update.py:139: aw = dict(facts) включает
  V; существует и в failure-free базисе; AB-1 не имел S0-контроля
  без noise) и переоткрытие после field-less prior (failure-
  артефакт, latest-уровень S1/S3/S4). Разложение следа по источникам
  и failure-free контроль S0 — задача LINEAGE-PERSISTENCE-1.
