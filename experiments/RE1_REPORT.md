# RE-1: ПЕРЕНОС И ВОССТАНОВЛЕНИЕ КОНТУРА: ОТЧЁТ (11.09.2026)

**Статус: PASS → CLOSED (вердикт профессора, 11.09).**

Канон: **RE-1 показал, что verified Knowledge может пережить
ротацию носителя и быть восстановлено без переприобретения, после
чего то же знание сохраняет способность участвовать в применении.
При этом восстановленное знание не переносится автоматически между
различными средами: в A оно дало SUCCESS, в B PARTIAL.**

Три пункта вердикта:
```
1. Restore ≠ reconstruction (снимок вернулся как есть; тот же
   kid; второго знания и переприобретения не было);
2. Память драйвера не подменяет Knowledge: ability to apply
   Knowledge must depend on the restored Knowledge carrier, not
   on residual driver state (E5/M9);
3. Restore не делает знание универсальным: persistence ≠
   applicability; A→B partial НЕ является generalization-
   результатом (RE-1 слишком узок для такого вывода).
```
Отметка вердикта: это **isolated RE-1 loop; not the full
production path; not a redefinition of persistence** — суженный
контур; полная production-траектория не проверялась.

RE-1 не смешивается с output-boundary веткой (отдельный вопрос).

Проверялся минимальный переносимый контур

```
[ state + applicable knowledge ]
        через
работа → снимок → rotation → восстановление → работа в другой среде
```

Не продуктовая ветка; портфель (recon1 r1 и прочие серии) не тронут.

## 1. Прогон (10 эпизодов; RAW RE1_E0..E9)

```
E0 env_bind   A (env=1)
E1 exposure   A
E2 acquisition A: fix-a → success → K1 (единственное знание)
E3 anchor      A: apply K1 → success
E4 rotation    (снимок; активная база пуста)
E5 apply_no_k  → no_knowledge   (применение невозможно: носителя нет)
E6 restore     (возврат зафиксированного снимка = тот же store)
E7 anchor_post_restore → success  (тот же kid; без переприобретения)
E8 env_bind   B (env=2, другой флаг среды)
E9 anchor_after_env_rotation → partial  (результат зафиксирован как есть)
```

## 2. Проверки

```
M1  локальный прогон (изолированные тенанты)              true

M4  короткий контур (≤12 эпизодов)                        true

M6  локальная валидация даёт разные результаты (A/B)      true
M7  без второго знания и без переприобретения             true

```

## 3. Что установлено

```
1. Перенос: состояние (среда/служба) и знание (носитель store +
   таблица kid→команда) переносятся; якорь работает до и после
   rotation (E3/E7) на ТОМ ЖЕ kid;
2. Восстановление = возврат зафиксированного снимка (не rebuild);
3. Без носителя применение невозможно (E5 → no_knowledge):
   «память драйвера» знание не подменяет;
4. Без переприобретения и второго знания; одна операция;
5. Разные исходы валидации честно записаны (A: success;
   B: partial) — знание не перезаписано, «success никогда не
   подсовывается»;
6. Слои (executor/knowledge/update/storage/evaluation/observer/
   strategy, включая изолированную A1-копию) — без изменений.
```

## 4. Ограничения (не расширять без слова)

```
* Среда A/B — локальные тенанты: файл состояния + скрипты
  fix-a/fix-aq в PATH (имена уже разрешены allowlist P7; слои
  не менялись). «Служба» — файловая, не systemd.
* Валидация — локальный детектор контура; evaluation-слой
  вызывался как в существующих драйверах (не изменялся).
* «Адаптация» в среде B = применение знания и фиксация нового
  результата (partial) без искажения знания; функция реализуется
  ровно настолько, насколько среда совпадает с условием знания.
* Narrowed-граница: 10 эпизодов, 1 знание (по дизайну).
```
