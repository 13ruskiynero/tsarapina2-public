# TSARAPINA EVENT-SUFFICIENCY-1: DESIGN (06.09.2026)

**Статус: ЗАКРЫТ — PASS (06.09.2026).** Эксперимент завершён
результатами E0–E2 (EVENT_SUFFICIENCY1_REPORT.md): информационная
граница (каналы идентичны), источник (env-факт различает ДО
действия), контекст применимости фиксируется и восстановим.
Протокол исполнения не требуется; код ветки (event_sufficiency1/)
сохранён как артефакт. Стратегия v0.3 НЕ менялась.

## 1. Вопрос (не «какой порог», а «достаточно ли информации»)

Может ли в текущем контуре существовать наблюдаемое событие,
которое различает STALE (знание есть, но мир изменился) и NOISE
(единичный внешний failure при исправном знании) **до выдачи
права на exploration**?

Три возможных исхода (формулировка профессора):
- (а) **НЕРАЗЛИЧИМЫ по всем доступным наблюдениям**: ни одна
  Strategy/trust-модель/routing не сможет решить безопасно; нужен
  новый датчик или новый способ наблюдения (граница наблюдателя);
- (б) **РАЗЛИЧИЕ УЖЕ В ИСТОРИИ**: есть смысл искать структурное
  событие (не числовой порог);
- (в) **НАБЛЮДАЕМО + не сводится к счётчику + воспроизводимо**:
  основание строить механизм EVENT-1.

Следствие: если (а) для первого же эпизода — это информационная
граница, а не дефект Strategy; «проблема не в отсутствии trust, а
в отсутствии информации» — закрытый результат.

## 2. Контекст (карта условий применимости памяти; формулировка
профессора 06.09.2026)

```
R1             contextual exploitation            ✅
AGG-1          evidence aggregation                ✅
TRUST-1        conflict / resolution               BOUNDARY
GENERALIZATION A/B → C                             ❌ (знание блокирует поиск)
SEB-1          absent exact → exploration          ✅
STALE-EXACT-1  existing exact → stale              BOUNDARY
```
- **SEB-1**: когда exact-знания НЕТ, структурного сигнала
  (пустой exact-пул) достаточно для безопасного exploration;
- **STALE-EXACT-1**: когда exact-знание ЕСТЬ, но неверно,
  последствия сами по себе не дают безопасного сигнала
  (H-S1 усилена: *в контуре нет наблюдаемого события, которое
  одновременно свидетельствует об устаревании и сохраняет
  шум-инвариантность*);
- отсутствие знания и недостоверность знания — РАЗНЫЕ
  вычислительные проблемы.

## 3. Факторизация E0–E4 (уровни сигнала; Strategy НЕ меняется
до показа существования сигнала)

### E0. Полный канал текущего контура (измерение, без изменений)
Собрать ВСЕ поля, доступные контуру на момент после не-success:
symptom (одинаков в stale/noise), action+command, result
(exit_code/stdout/stderr), state_before/state_after (ПОЛНЫЕ
снимки 9 сенсоров: disk, memory, load, service:ssh, service:tsasvc,
symptom, ports, process:sshd, log:ssh), evaluation (outcome),
conflict-история, версии знаний.
Метод: офлайн-анализ логов STALE-EXACT-1 (валидные прогоны) +
целевые прогоны серий stale/noise на v0.3 (F0-механика, без
declare): для каждой пары (stale-эпизод, noise-эпизод) сравнить
ВСЕ каналы: какие поля различаются? Гипотеза E0: реалистичный
noise (внешний сбой после fix-a: «симптом исчез, сервис failed»)
дает ту же картину, что stale → неразличимость по E0-каналам в
первом эпизоде.
Метрика E0: доля каналов, различающих stale/noise (ожидание: 0).

### E1. Изменение мира наблюдаемо (новый факт среды; Observer)
Политика эксперимента: 'extra' (скрытое условие STALE-EXACT-1)
становится ОТДЕЛЬНЫМ наблюдаемым фактом среды (subject=tsasvc,
property=extra, value=present/absent), НО НЕ симптомом (symptom
по-прежнему 'a').
Вопросы: (1) видит ли Observer изменение (факт extra до действия
в новом мире); (2) возникает ли различие stale/noise ДО действия
и ДО exploration (stale: контекст обучения extra=absent, текущий
extra=present; noise: тот же контекст, что при обучении); (3)
связано ли оно с применимостью знания (fix-a проверено при
extra=absent).
Ожидание: stale/noise различимы ДО первого действия по
контекстному факту → «проблема была в отсутствии информации».

### E2. Контекст применимости знания (Knowledge/Experience)
Знание фиксирует контекст своей проверки: при learn/update в
запись добавляются context_conditions (снимок наблюдаемых env-
фактов на момент проверки последствия; НЕ интерпретация).
Вопрос: можно ли получить «same symptom, same action, different
context → different consequence» с сохранением provenance?
Метод: серии stale/noise с фиксацией контекста; проверки:
(1) контекст восстановим по цепочке knowledge→experience→raw;
(2) «вне контекста проверки» встречается ВСЕГДА в stale и
НИКОГДА в noise; (3) конфликтные/retracted-версии не теряют
контекст.
ЗАПРЕТ: не менять Strategy (никакого «применять/не применять по
контексту» — E2 только фиксация и измерение).

### E3. История последствий (офлайн-анализ; структурный паттерн)
Без новых фактов: сетка серий над полигоном: stale (s,s,s,f,f),
noise (s,s,f,s,s), noise2 (s,f,s,f,s), stale-late (s,s,s,s,f,f)
и т.п. — измерение, НЕ механика: какие комбинации истории
существуют и какие РЕАЛЬНО предсказывают исход следующего эпизода
(метрика: точность паттерна → исход следующего эпизода;
перекрёстная проверка на отложенных сериях).
Вопрос: различимы ли stale/noise по позиции failure в истории,
НЕ сводясь к «k-й failure подряд»? Паттерн-кандидат: «первый
failure после непрерывного успешного хвоста длины ≥ L» против
«failure внутри перемежающейся истории» — проверяется как
ИЗМЕРЕНИЕ предсказательной силы, не как механизм.
Гипотеза H-E3: различение возможно ТОЛЬКО после второго
последствия (s→f→f для stale против s→f→s для noise); безопасное
различение ДО первого повторного действия невозможно; цена
безопасности = отложенное право искать.

### E4. Контроль (обязателен для любого найденного индикатора)
Для каждого кандидата-индикатора из E1/E2/E3: same history, same
symptom, same action, NOISE → индикатор НЕ должен срабатывать;
контрсерия «stale с историей, имитирующей noise-паттерн» (s,f,s,
затем мир меняется: f) — индикатор должен сработать на ПЕРВОМ f
после смены мира, несмотря на шумовую историю. Цель: исключить
«индикатор, распознающий специально нарисованный эксперимент».
Индикаторы фиксируются ДО измерения их силы.

## 4. Критерии и маршруты

- (а): все E0-каналы не различают stale/noise в первом эпизоде и
  E3 показывает: различение требует ≥2 последствий → результат
  «информационная граница наблюдателя: безопасное решение в
  первом эпизоде невозможно при данном наборе наблюдений; нужен
  новый датчик/способ наблюдения (E1-уровень)»;
- (б): E3 находит паттерн истории с воспроизводимой
  предсказательной силой, не сводящийся к счётчику → «структурное
  событие существует в истории» → основание для EVENT-механики
  (следующий дизайн);
- (в): E1/E2 дают наблюдаемое различие ДО действия + воспроизводимо
  + не счётчик → «проблема была в информации» → механизм
  контекстной применимости (следующий дизайн; Strategy — только
  тогда).

**Запреты:** механика в Strategy до показа существования сигнала;
N-failure пороги как решение (разрешены только как ИЗМЕРЕНИЕ в
E3); trust-числа; причинная модель; подгонка индикаторов
(фиксация до измерения); изменение Knowledge/Experience за
пределами E2-фиксации контекста.
