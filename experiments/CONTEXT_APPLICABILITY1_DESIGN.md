## 1. Вопрос

> Может ли Strategy использовать наблюдаемый контекст применимости,
> чтобы выбирать между несколькими exact-кандидатами, не разрушая
> уже установленные свойства v0.3?

НЕ «понять мир»; НЕ «вывести скрытое условие» (E0: если условие не
наблюдаемо — информационный потолок). Условие НАБЛЮДАЕМО (E1:
envfact; E2: фиксация/восстановимость контекста проверки). Здесь
проверяется ТОЛЬКО использование:

> наблюдаемые условия могут быть частью адреса проверенного знания.

Проверяемое утверждение (узкое): выбор между exact-кандидатами
идёт по паре (symptom, context), а не по recency. Кандидат на
архитектурную единицу: Knowledge = what + where/under-what-
condition verified + provenance → адрес (symptom, context) → action.
НЕ «contextual reasoning» — только адресация.

## 2. Конструкция (базовая)

```
Knowledge K1: symptom=a, action=fix-a,  verified under ctx=absent
Knowledge K2: symptom=a, action=fix-a2, verified under ctx=present
текущий контекст: ctx_now (envfact: extra present/absent)
```
v0.3 при symptom=a видит два exact-кандидата и выбирает по recency
(свежайший: K2, если учили позже) — при ctx=absent это НЕВЕРНО.
Новая механика добавляет ТОЛЬКО: current_context ↔ knowledge_context.

## 3. Механика (experimental; strategy_v6)

- ctx знания: по цепочке knowledge → опыт → действие → args.ctx_extra
  (фиксация E2; восстановимость показана). Знание без ctx
  (ctx=None — старые данные) НЕ фильтруется (пригодно всегда) —
  иначе ломается регрессия существующих знаний;
- ctx_now: envfact-сенсор; при недоступности (None) фильтр выключен
  (поведение v0.3);
- выбор exact: пригодные = exact-знания с ctx(r) == ctx_now (плюс
  ctx=None-знания); если пригодные есть → S2, recency ТОЛЬКО внутри
  пригодных (tie-break); если exact есть, но пригодных НЕТ →
  S3-остановка (rationale: context_mismatch — знание вне контекста
  проверки; не применять вслепую; без exploration в CA-1: цена —
  новый learn; exploration-механика — отдельный вопрос, здесь не
  проверяется);
- остальные ветки (конфликт → S3; exact-пусто → SEB routing v0.3;
  broad-гипотеза; S1) — ПОВЕДЕНИЕ v0.3 без изменений;
- никакого trust; никакого recency как основного правила; никакого
  вывода контекста из результата; никакой generalization.

## 4. Сценарии прогона (полигон tsasvc; v0.3-слой не трогается)

Обучение (наблюдаемые миры):
- L1: мир absent (a): learn fix-a (ctx_extra=absent фиксируется);
- L2: мир present (a + extra-видимый): learn fix-a2 (ctx=present).

Задачи (чередующиеся, N=4 каждую):
- T1: ctx=absent → ожидание S2 fix-a (1 действие, success); контроль
  перевёртыша: K2 (fix-a2) учили ПОЗЖЕ — recency v0.3 выбрал бы
  fix-a2 (неверно при absent);
- T2: ctx=present → ожидание S2 fix-a2 (1 действие);
- T3: чередование absent/present ×6 → правильный выбор каждый раз
  (не залипание на свежайшем; M3: 1 действие на каждый);
- T4 (старые свойства, по списку профессора):
  known A (только L1-знание) → 1 действие;
  AB (learn ab) → 1 действие fix-ab;
  C (новый симптом, exact пуст) → exploration-механика v0.3
  (гипотеза → перебор → fix-c);
  S3 (объявленный конфликт двух знаний ОДНОГО ctx) → S3 сохранён;
  swap: задача после знания → S2 (модель не участвует);
  determinism: повторный suggest при том же состоянии идентичен.

## 5. Критерии

PASS: T1/T2/T3 — правильный контекстный выбор (1 действие, success,
6/6 чередований без ошибок); T4 — все свойства v0.3 сохранены.
BOUNDARY (если): контекстный фильтр ломает любое свойство T4, или
T3 залипает (M3>1), или ctx не восстанавливается хотя бы в одном
прогоне. Никакой подгонки: порядок обучения (L2 после L1) намеренно
ставит recency против правильного ответа в T1.

## 6. Запреты

без trust; без N-счётчиков; без вывода ctx из результата; без
изменения Knowledge/Update/Experience API (ctx — данные в
action.args, читаемые по цепочке); основная Strategy v0.3 не
меняется; без переименования в «reasoning».
